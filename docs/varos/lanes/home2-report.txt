BOARDLESS DOCUMENT DESIGN
- file.new clamps artboard counts to at least one; changing that would change the New Document contract and recent presets. Added the engine command file.newBoard {} instead (registered metadata, always enabled, reachable through engine/control/MCP).
- It creates an ordinary native Document with an empty artboards vector, default units/grid, an untitled name and creation metadata. There is no hidden artboard, no new serde field and no schema change. Existing file.new and old documents are untouched.
- The canvas already skips page clipping when artboards is empty and draws no page. Rulers use the document's zero origin. Cmd+0 fits visible effect-aware art bounds; an empty board starts centred at the ruler origin using a view-only 800×600 target, never a persisted page.
- Boardless raster export uses visible art bounds. PDF uses a temporary output-only page around those same bounds because the upstream PDF writer needs a page. Hidden art is omitted from bounds and effect reach is included.
- PDF native editing data keeps the ORIGINAL zero-artboard document, including the common Export As/useArtboards:false path. Export never inserts a page into the live/saved native document.
- Default print treats zero artboards like upstream Ignore Artboards. Actual print already flattens raster effects before layout. Empty artwork exports/prints return an error; explicit invalid artboard selections are validated.
- The existing Artboard tool/engine artboard.new can add a board later; Undo returns to zero boards. Upstream still prevents deleting the last artboard with artboard.delete; Undo of the addition is supported. Artboard-specific flows retain upstream validation.
