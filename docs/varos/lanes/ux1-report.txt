Three owner requests: instant zoom, several panels open at once, outer scale handles on area type.

1. ZOOM WITHOUT GLIDE ("Smooth Zoom" preference, off by default)
What the user sees: Preferences › General › Options has a new "Smooth Zoom" checkbox, off.
Off: Cmd-wheel, Alt-wheel and (with Zoom with Mouse Wheel) a plain wheel notch zoom all at once,
in the frame the notch arrives, with no glide frames. On: upstream's glide as before.
Where the glide came from: egui spreads mouse-wheel notches over ~0.1 s (Cmd-wheel is egui's
zoom, Alt-wheel a smoothed scroll the canvas turns into zoom), and with Zoom with Mouse Wheel the
canvas glides each notch itself (#888, WHEEL_GLIDE). Cmd +/-, Actual Size/Fit, the Zoom tool's
click and marquee, trackpad pinch and the Navigator were already instant.
Name: "Smooth Zoom", not "Animate Zoom": Performance › "Animated Zoom" already exists (the Zoom
tool's drag/hold zoom, an upstream preference) and two near-identical names would confuse.
That press-and-hold zoom of the Zoom tool is a user-driven continuous zoom, left as it was.

2. SEVERAL PANELS OPEN AT ONCE (dock "keep open" mode, on by default)
What the user sees: clicking Character then Paragraph in the right icon column keeps both open.
They stack top to bottom left of the column (oldest on top, newest below), each card with the
same title strip, panel menu and » (put away) as upstream's flyout; the stack scrolls when taller
than the window. Every open panel's icon is lit. Clicking a lit icon closes only that panel;
each card's » closes only its own. With one panel open it looks exactly as before (upstream draws
it); from two on the stack draws them. Window › <panel> toggles the same way and ticks every open
panel. The open set is saved in ui.json (UiState.varos_panel_stack {keep_open, open}).
User Interface › Auto-Collapse Iconic Panels on = flyouts are transient, so the column goes back
to upstream's one-at-a-time swap. keep_open=false also gives upstream's swap (no UI toggle yet).
Design: upstream's UiState.open_panel stays "the newest open panel", so all upstream code
(workspaces, docking, floating, shortcuts) keeps working; varos::panel_stack::reconcile follows
what upstream did to open_panel each frame (opened -> added; put away -> removed; floated or back
in the expanded dock -> leaves the stack; a workspace applied -> stack restarts from its panel).

3. OUTER SCALE HANDLES ON AREA TYPE
What the user sees: with area type selected (Selection tool, bounding box on), the 8 square
handles still resize the frame (text reflows, same size). Four small filled circles in the
selection colour sit 10 screen points outside each corner (diagonally); dragging one scales the
whole object like a shape: frame, type size and leading together, always in proportion (no Shift
needed), Alt scales about the centre. The cursor over them is the corner's diagonal resize cursor.
One undo step ("Scale"). They are hit-tested before the frame handles. Rectangles and other
objects are unchanged (their corners keep the rotate zone). Smart Guides snapping applies as for
any bounding-box scale.
Mechanism: the same object.transform the bounding box uses, without typeAreas (upstream's own
"scale the type too" path: the type's size and leading scale through its transform and the
Character panel reports the scaled size, #1034). No engine change.
