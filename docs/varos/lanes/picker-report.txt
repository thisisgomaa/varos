WHAT THE PERSON WILL SEE
- The Color panel (icon column, stack, floating or docked) is the 240 pt Varos picker: header with Wheel · Sliders · Harmony · Gradient (dimmed, tooltip "Gradient (coming soon)") on the left, eyedropper and × on the right.
- Wheel: hue ring with the HSV triangle turning with the hue; markers; Default squares top right (white|black, = Default Fill and Stroke, D); readout bottom left in the slider mode (H/S/B by default, mono font); Fill/Stroke cluster bottom right (click circle = focus, arrow = swap, ⌀ = None). Then "# RRGGBB", alpha slider, "100%". Then 9 recent colours and ▾ for the drawer.
- Sliders: mode menu (HSB HSL RGB CMYK Lab Web) + hex at left, cluster top right, one row per channel (track, knob, editable value), an "A" alpha row.
- Harmony: 8 rule buttons, the wheel with linked hue markers, 6 chips and variation rows; a click on a chip sets the focused target.
- Double-click on the toolbar Fill/Stroke proxy: focuses that proxy and shows the Color panel (no modal). Escape with the pointer over the picker closes the panel (never undoes). X / Shift+X / D / / / I are upstream's existing shortcuts; the picker follows them.
- Panel menu › Classic brings back upstream's sliders/spectrum body (kept, persisted).
- Each drag (ring, triangle, slider, alpha) = one undo step; typing hex/values or clicking a chip = one step; nothing is written without a visible change; a mixed selection stays untouched until the first change.
- Tab, slider mode, harmony rule, drawer open/tab, recent colours (up to 18) and Classic are saved in ui.json under "varos_picker".

WHAT IS LEFT / DROPPED (and why)
- Mini config (192 pt popover on the page-colour chip): not built; not in this lane's definition of done.
- Drawer "Board" tab (colours used on the active artboard): dropped; varos-next has no cheap per-artboard colour scan. Drawer has Recent · Document (document solid swatches).
- Gradient tab body: disabled by design (tooltip only).
- CMYK and Lab sliders are the old picker's naive (not colour-managed) maths and write sRGB, as the work order says. A CMYK object edited in the picker becomes RGB (upstream's RGB/HSB modes do the same with keepModel). For colour-managed CMYK that keeps the model, panel menu › Classic. I first tried upstream's colour engine for CMYK: its RGB→CMYK→RGB is not a round trip for dark colours (black drifted 0 → 0.165 → 0.279 per trip), so I reverted to the naive maths.
- Alpha = opacity of the targeted fill/stroke appearance item (Appearance panel's active item of that kind, else the topmost). With objects whose item sits at different stack positions, alpha is written on release only (no live preview), as one undo group. Nothing selected: alpha controls are disabled. Gradient stops: alpha still targets the layer opacity, not the stop's opacity.
- The eyedropper button selects upstream's Eyedropper tool (I); the old picker's canvas sampling inside the panel was not ported.
- Tint of a global/spot swatch: editing in the picker writes a process colour (link dropped); Classic still shows Tint mode.
- `ui.colorPicker` (modal) still exists for agents/CLI/MCP and is still listed in the command palette as "Color Picker…"; a person running that palette entry still gets the modal. The proxy double-click (the UI path) no longer opens it. Moderator's call whether to reroute or hide the palette entry.
- Translations of the new strings (23 languages) were written by me, not reviewed by native speakers.
- Concurrency note: lane-panels2 was editing crates/ui-egui/src/dock.rs at the same time; my dock.rs change is 4 lines in panel_width() — possible merge conflict.
- Pre-existing clippy failure in varos/home_capture.rs (see above) blocks the strict clippy gate on this toolchain regardless of this lane.
