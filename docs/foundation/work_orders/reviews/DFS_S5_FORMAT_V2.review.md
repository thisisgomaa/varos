# Review — `DFS_S5_FORMAT_V2.md` + draft `ADR-0008-vrs-format-versioning.md`

Reviewer: independent plan reviewer (read-only; no cargo run). Code read at `b36e850` on `claude/sweet-cerf-1sg30t`, plus the S6-A worktree `feat/dfs-s6-a-pure-pdf` and a full-history clone (the repo clone is shallow). Every `file:line` below was opened.

## Verdict: APPROVE WITH CHANGES
1. The core reading of D3 is right and minimal. v2 is the same model with the stamp raised, `deny_unknown_fields` and a version gate before typed decode. History shows this cannot refuse a real Varos v1 file because of an unknown key (F3).
2. One data-loss hole: load runs a canonical check (step 9) that save does not, so a saved file can become unopenable (F1).
3. Two gaps in who owns what will stall work. B's version bump breaks S6-A's byte-identical fixtures, and nobody owns the corpus check that protects Ahmed's own files (F2, F3).
4. About 30% can be cut without losing any acceptance item: the v2 required-key pass, the JSON depth scanner, most of the old-reader harness, and `flate2` (F4–F7). S5-C is justified by the spec, but it should keep only the rules about what the user drew (F8).
5. ADR rule 3 is correct but worded as a proof obligation that can never apply. State the simple rule (F9).

## Findings

1. **P1 — Save skips the canonical check that load enforces, so a saved v2 file can refuse to reopen.**
   - *Evidence:* §3 step 9 (`NotCanonical`) runs only on load. "**Save:** … runs `check_structure` + `validate` + the size cap". R5 then tells C to *drop* any rule the editor cannot guarantee, but step 9 still refuses that state on load.
   - Concrete gap: C's "roots are Layers" passes when `roots` is empty. `sync_tree` then adds "Layer 1" (`model.rs:1583–1600`), so load says `NotCanonical`.
   - The editor normalizes only inside `commit()` (`editor.rs:3050`), so a direct write outside begin/commit is saved as-is. The spec (§2) says: "Apply matching validation before Save so this build cannot write a document it will refuse to reopen."
   - *Change:* replace the **Save:** sentence with: "**Save:** `encode_model` runs `check_structure` on `doc`. It then runs the step-7 normalizer on a clone (`sync_tree`; a clip demotion ⇒ `SaveRefused(Invalid::BadMask)`), then `validate` and the size cap, and serializes the normalized clone. The editor's document is never mutated."
   - Add the test `every_saved_doc_reopens`: for every document built in `format_v2.rs`/`format_validate.rs`, `decode_model(encode_model(d)?)` is `Ok`.
   - Add encode time to `decode_timing_at_caps`, because S3 pays it every 30 s.
2. **P1 — B's bump breaks S6-A's byte-identical fixtures, but the work order hands the regeneration to D/S6-A.**
   - *Evidence:* S6-A's worktree `write.rs:12` imports `VRS_VERSION`, and `:283` writes it into the catalog. `export_pdf.rs:136–138` compares `write_pdf` byte for byte against `native_demo.pdf` **and** `native_rich.pdf`.
   - B changes `VRS_VERSION` to 2 through the alias. B must also keep "existing tests … green unchanged" and "must not touch `varos-pdf`, fixtures". So B's own gate fails if S6-A is merged first, and S6-A is being built now.
   - *Change (§5 hot spots):* "S6's `native_demo.pdf` is regenerated by whichever lands second (the version key changes)" → "If S6-A is merged first, **B** regenerates `varos-pdf/tests/fixtures/native_demo.pdf` and `native_rich.pdf`. It proves with `cmp -l` that each file differs in exactly 2 bytes (`"varos":1→2` in the blob, `/VAROS_SchemaVersion 1→2`; both are the same length, so no offsets move). Any other difference stops B."
   - Add both paths to B's owned files.
3. **P1 — The corpus check over Ahmed's real files has no owner and no hand-test step.**
   - *Evidence:* R3 and the ADR's Consequences make it a precondition for merging to `main`. Yet no piece lists `corpus_check`, §1 does not mention it, and the cloud session cannot see his Mac.
   - Good news, from a full-history audit:
     - The first build that could save `.vrs` is `7a5b3c8` (2026-07-02). No earlier app code wrote files.
     - Since then no persisted field was removed or renamed in `model.rs`/`units.rs`. `d556acf` kept the `fill`/`stroke` keys and only changed their type. `0f3c629` was a fmt reflow that re-added every field it removed.
     - The singular `artboard` key was removed in `d1e5f80` (2026-06-30), before any save existed.
     - So `deny_unknown_fields` on v1 is safe. The remaining risk is *structural* refusals: broken clips, dangling leaves, ranges.
   - *Change:*
     - Add `varos-pdf/tests/corpus_check.rs` to S5-E's owned files. It is `#[ignore]`, reads `VAROS_CORPUS_DIR`, prints OK or the refusal reason for each file, and never writes.
     - Add to §1 a hand test **0 (before merge to `main`)**: "`VAROS_CORPUS_DIR=~/Documents cargo test -p varos-pdf --test corpus_check -- --ignored --nocapture`. Send the output. Any refusal of one of your files blocks the merge."
     - Put the history evidence above into R3.
4. **P2 — Delete the v2 required-key pass (`V2DocKeys`/`V2ArtboardKeys`).**
   - *Evidence:* It is not an acceptance item. Spec §2's v2 row says only "Validate current schema", and D3 asks for version refusals, not key presence.
   - No Varos writer ever omits these keys; none of them is `skip_serializing` (`model.rs:345–363`, `:498–547`).
   - It costs a second full JSON pass over up to 32 MiB. It also makes the legacy `groups`/`group_of` keys *mandatory* in v2 ("every `Document` key"), which freezes keys the format wants retired.
   - *Change:*
     - Delete the step-5 sentence "**For v2 only**, a second cheap key pass … `hidden,locked}`." Keep the v1 / `[]` sentence.
     - Delete `v2_missing_legacy_defaulted_key_is_malformed`.
     - ADR rule 2, second bullet → "v1 files keep their legacy Serde defaults."
5. **P2 — Delete the custom JSON depth scanner and `max_json_depth`.**
   - *Evidence:* serde_json 1.0.150 has `remaining_depth: 128` (`de.rs:63`), and it is active; the work order verified this itself in §2.
   - Skipped unknown content goes through `ignore_value`, which is iterative with a heap stack (`de.rs:1102–1150`), so deep junk cannot overflow the stack.
   - The model has no recursive types. Typed depth is about 6.
   - *Change:*
     - Step 3: "Then our own byte-scanner depth check (≤ `max_json_depth`, outside strings), with serde's 128 limit as a backstop" → "Depth: serde_json's built-in 128-level limit; no own scanner."
     - Remove `max_json_depth` and `LimitKind::JsonDepth`. Keep `json_depth_over_limit_refused`, because it proves the serde limit.
6. **P2 — Shrink the old-reader harness to what it actually proves.**
   - *Evidence:* Every build that can save has the header-first gate: from `7a5b3c8:varos-core/src/file.rs:38` through `ecf67f5:file.rs:33`. Every Varos PDF has written `/VAROS_Model` since `b06194a:varos-pdf/src/lib.rs:194`.
   - So "old readers refuse v2" is just test (a) plus "the model is still under `/VAROS_Model`, unfiltered". The generic copy + `Tripwire` + `sync_tree` closure proves `2 > 1`, and after the generic edits it is no longer "verbatim".
   - ADR Consequences says "Builds older than that check cannot be protected". No such build exists.
   - *Change:*
     - Replace the harness bullets with: "`old_reader_harness.rs` holds a ≤15-line verbatim copy of `ecf67f5:file.rs:28–35` (the typed decode comes after the gate, so the gate returns first by construction) and of the old `/VAROS_Model` lookup (`ecf67f5:lib.rs:343–356`). It asserts that the v2 JSON and PDF fixtures give 'newer Varos (v2)'. No generics, no counter."
     - Keep hand test 3.
     - ADR: replace that sentence with "Every `.vrs`-capable build since `7a5b3c8` has this check."
7. **P2 — S5-D: keep the pre-gate and the ObjStm filter, but drop `flate2`.**
   - *Evidence (necessity):* a byte cap plus lopdf's own limits is **not** enough. lopdf 0.43 inflates xref streams while parsing the xref, and every `/ObjStm`, with no cap (`reader.rs:987–989`). On the encrypted path it ignores the filter (`reader.rs:836`, `:845`). The pre-gate and the filter are the minimum.
   - *Evidence (flate2):* spec §3 says "No new crates or dependency-edge changes are required". Varos writes the model unfiltered (`lib.rs:252`). An app that re-compresses the model will almost certainly also write object/xref streams, and the pre-gate refuses those anyway.
   - *Change:*
     - D step 4 → "no `/Filter` ⇒ raw content (≤ `max_model_bytes`); any filter ⇒ `UnsupportedPdf("model encoding")`."
     - Drop `flate2` from D's owned files.
     - Replace the two `flate_*` tests with `filtered_model_refused`.
     - Revisit only if hand test 4 finds a Preview output that passes the pre-gate with a Flate model (this is R7's own default).
8. **P2 — S5-C is justified, but trim it to the rules about authored meaning. Ids are unique per kind.**
   - *Evidence:* The spec's own list backs it (§2: non-finite values, negative sizes/strokes, opacity/colors, units/PPI, mask parentage), and it is needed for acceptance (c).
   - These rules are just what `sync_tree` guarantees (`model.rs:1558–1667`): "legacy registry empty; no nested live xform; no empty group; no orphan path". Step 7 produces them and step 9 checks them. In `validate` they add nothing on load. On save they are the rules most likely to refuse a user's save (R5).
   - Existing tests reuse ids across kinds. In `vrs.rs:21–31` path 1, anchor 1 and Layer node 1 all coexist.
   - *Change:*
     - Delete C's "Legacy and xform" bullet and the "no orphan paths; no empty Groups" clause. After F1, the save normalizer covers them.
     - B step 6: "unique path, node and legacy-group ids" → "ids unique within each kind; cross-kind reuse is legal (R10)".
     - C ranges: "artboard `w`,`h` > 0" → "≥ 0" unless an editor invariant is cited. The spec says "negative sizes".
9. **P2 — ADR rule 3 (flagged by the drafter): keep the rule, state it simply.**
   - *Evidence:* Rule 2 puts `deny_unknown_fields` on every struct. After that, *no* writer-side addition can be additive-safe for v2 readers: any new key or variant becomes "malformed". The "needs proof" category is empty, so that wording invites debate about a case that cannot occur.
   - *Change:* replace rule 3's first three sentences with: "**Any change to what the writer can emit** (a new, removed or renamed key, a new enum variant, a changed type, unit or default) **raises the format number.** Reader-only relaxations (accepting input no writer emits yet) do not." Keep the last sentence (migration, fixtures, `VRS_FORMAT.md`).
   - Add to Consequences: "An older build refuses a newer file even when the new feature is unused in it. Stamping the minimum needed version is a possible later ADR, not v2."
10. **P3 — ADR text hygiene.**
    - Rules 2 and 6 hard-code the key list and the limit numbers. After F4 the key list is gone. Move the numbers to `VRS_FORMAT.md`, and keep only the policy in the ADR ("lowered after measurement; raising needs the owner").
    - "Ahmed accepts by editing this line" → "The moderator records Ahmed's words and the date in STATUS, then sets this line." He is not the one editing files.
11. **P3 — Sequencing.**
    - E "starts at base immediately" but then idles until C+D are done. Make the v1 fixture generation B's **first commit** at base, before the bump, and add those fixture paths to B's owned files.
    - E then starts after C+D. Sonnet is fine for E.
    - After F4–F7, B drops from L to M, and the stage has a real chance of fitting its day.
12. **P3 — Overlaps.**
    - S3's app-side `Loaded { blob, generation, fell_back }` shares its name with core `format::Loaded`. Rename S3's to `SnapshotPick`.
    - S3's `MAX_SNAPSHOT_BYTES` should become `Limits::DEFAULT.max_model_bytes`.
    - S6-A's `has_embedded_model` is now a byte scan (S4/S6 review F2), so no second name-tree walker appears.
    - The name-tree fallback in D is optional. Every Varos PDF has had `/VAROS_Model` since `b06194a`. It can be dropped (removing `max_pdf_depth` and 3 tests) unless hand test 4 needs it.
13. **P3 — `Invalid::NonFinite { what }` must name the object** (path name or id). A refused save has to tell Ahmed which shape to fix, or the document is stuck unsaveable.
