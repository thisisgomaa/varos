# Review — `docs/specs/UI_SYSTEM.md` · angle: visual system, kit, tokens, fonts

Reviewer: independent, read-only on the repo (no build of `varos`, no window). Spec read in full at `6b37c2b`, plus `UI_DIRECTION.md`, `UI_VISION_MOCKUP.html`, audits 01–05, DFS S1 §3.6, S2 §3.7, QUICK_WINS QW6, `shell/tokens.rs`, `boxtree.rs`, `ui.rs` (fonts, `toggle_row`, `dlg_btn`), the fork `tree.rs`, and the egui/epaint 0.35.0 sources in the cargo registry.
**Measured, outside the repo (scratchpad only):** IBM Plex from IBM's npm packages (`@ibm/plex-sans` 1.1.0, `plex-mono` 2.5.0, `plex-sans-arabic` 1.1.0, all `OFL-1.1`). TTF sizes come from each WOFF header's `totalSfntSize` field. Glyph coverage and OpenType features come from parsing `cmap`/`GSUB`/`GPOS`. The Arabic layout is from a 30-line `epaint =0.35.0` probe using `layout_no_wrap` at ppp 1. This is layout output, not pixels, and nothing was seen in a window.

## Verdict: REQUEST CHANGES
1. The visual laws (L25–L30), the token groups and the "one `look()`" kit are the right system. The kit is small, and no component has only one use. But it is **incomplete**: switch, text field and tab chip are missing (F6).
2. The kit cannot compile where §3.1 puts it. It lives in the lib, but its API uses the bin's `CommandId`/`Request`/`HomeId` (F1).
3. Q4's "on" state is not what the mockup says, and it leaves the switch, segments, the measure HUD and drop targets undecided (F2). The FAINT→MUTED and label-size changes quietly undo the mockup, S2 §3.7 and the queued QW6, while the Arabic summary says "the look stays as it is" (F3).
4. The font facts in §6 R2 are wrong, and two gaps are unmeasured: egui 0.35 does shape Arabic but has no bidi, and ⌥/⌃ exist in no proposed font, so Mac hints would draw tofu (F4).
5. Q3 is honest about reversing 07-05, but it bundles three decisions into one, and L28 misses egui's own motion (F5). The goldens are feasible headless with a few preconditions (F7).

## Findings

**F1 · P1 — The kit's placement contradicts the kit's API.** §3.1 puts `shell/kit/*` in the **lib** ("Reusable, window-free pieces live in the lib"). `lib.rs` exports only `shell` and `storage`. `AppCommand`, `ui/commands.rs`, `ui/request.rs` and `ui/homes.rs` are **bin** modules (`main.rs:28-39`). Yet §3.3 has `enum Act { Cmd(CommandId), Req(Request), .. }`, `Tip::Cmd(CommandId)`, `m.cmd(id)` and `section(.., more: Option<HomeId>, ..)`. A lib cannot name bin types.
*Change:* §3.3 "`pub enum Act { Cmd(CommandId), Req(Request), Off(&'static str) }`" → "`pub enum Act<A> { Do(A), Off(&'static str) }` (the kit is generic over the action; the bin instantiates `A = Request`). Menu rows and `Tip` take a resolved `RowSpec { label, hint, enabled: Result<(), &'static str> }` built by `ui/commands.rs`, and `section` takes `more: bool` and returns `SectionHit::More`". The kit then stays in the lib, and testkit needs no bin types.

**F2 · P1 — The "on" state resolution does not match the mockup and is incomplete.** §4 says "Toggles and segments 'on' = SURFACE fill + 2 px ACCENT underline (mockup `.cbtn.on`)". The mockup's `.cbtn.on` is `color:var(--text)` plus a **10×2** accent bar, centred, 1 px from the bottom, with **no fill**. What the mockup uses for a chosen tab-like option is `.gtab.on{background:var(--surface);color:var(--text)}`, with no azure (UI_DIRECTION l.61-62 says the same). Four other cases are not decided at all:
the switch: `toggle_row`, 9 call sites, ACCENT capsule at `RCAP` (`ui.rs:5175`); · the measure HUD: the mockup `.hud` is an azure fill with white text, and white on ACCENT is **3.53:1**, which fails L29's 4.5:1; · the drop target: `list_row` "drop", and the docking slot after Q3; · the text caret: egui's default `text_cursor` is a cold blue that `tokens::apply` never sets.

*Change:* §4 Button row → "Tool = ACCENT fill + ON_ACCENT icon (`.tbtn.on`). Icon toggle on = TEXT icon + `ON_BAR` 10×2 ACCENT bar at bottom−1 (`.cbtn.on`), no fill. Segment/tab on = SURFACE fill + TEXT (`.gtab.on`), no azure. Switch on = ACCENT track (active). No text is ever drawn on ACCENT." L27 → "ACCENT only for: current tool, toggle-on bar, switch-on, selection (rows, reference point, paint target, text selection), keyboard focus, text caret, drop target". Change the L27 test to match that list. Q4 gains "measure HUD = PANEL + LINE (today's code); the mockup's azure HUD is retired". Q4 "RCAP 11 = box tabs only" → "RCAP = box tabs, switches, strip chevrons" (today's three users, per the `tokens.rs:58` comment).

**F3 · P1 — Label colour and size quietly overturn the mockup, S2 §3.7 and QW6.**
L29 limits FAINT to disabled/placeholder text. The mockup draws **all** micro-labels (`.slabel`), field labels (`.fld .l`, `.mini .l`), the status bar, ruler numbers and `⋯` in FAINT. S2 §3.7, which the spec says it builds on, specifies "`RECENT` micro-label (9.5 px, uppercase, FAINT)" and FAINT timestamps. · `T_MICRO` is 9.5, but QW6 (queued, owns `tokens.rs`) raises section labels to **10.5** and icon glyphs to **18 px**. §3.4 allows `IC` 16 / `IC_S` 13 and "icons in exactly two sizes", so U3 would silently revert QW6 after Ahmed hand-tested it. · The Arabic summary says "قواعد UI_DIRECTION زي ما هي" (the UI_DIRECTION rules stay as they are). · Measured contrast: FAINT 3.26 on PANEL, 2.98 on SURFACE; MUTED 5.12 / 4.68.

*Change:* Add to Q4: "Labels, status text and ruler numerals move FAINT→MUTED (they fail 4.5:1 at 3.26/2.98); the mockup and S2 §3.7 are amended in U3-F". · `T_MICRO` → "size = QW6's value after Ahmed's hand test (10.5 today)". · `IC`: "sizes = QW6's measured set". · Hot-file queue `shell/tokens.rs`: "QW6 → **U0-A** → U3-F". Reuse QW6's `token_contrast_tests`; do not add a second one. · Summary line 14 → "الألوان والقواعد زي ما هي، بس الـlabels الرمادي الباهت هتبقى أوضح، والزوايا/المسافات هتتكتب زي ما وافقت عليها في 07-04/07-08" (the colours and rules stay the same, but the faint grey labels get clearer, and the corners/spacing are written down as you approved on 07-04/07-08).

**F4 · P1 — The font facts are wrong, and there are glyph and format holes.**
(a) §6 R2 says egui "applies no OpenType features". That is wrong. epaint 0.35 shapes with `harfrust`: `shape_text` calls `buffer.guess_segment_properties()` and then `shaper.shape(buffer, &[])`. So the font's default GSUB/GPOS features (kern, liga, mark, Arabic init/medi/fina/rlig) are applied. Only caller-chosen features such as `tnum` are impossible.
(b) Plex Sans digits are already tabular: all ten have a 600-unit advance. `T_NUM` mono is therefore a style choice (mockup `.v`), not the only way to get tabular figures.
(c) Arabic, measured with the probe:
A single Arabic word **joins and orders correctly**: "فاروس" is 5 glyphs from right to left, and ف takes its initial form (9 px wide vs 18 px isolated). · There is **no bidi and no script itemisation**. epaint splits runs by font face (`segment_into_runs`, and its own comment says "would need script-aware splitting once RTL/bidi support is added"). · With Plex Sans first in the family, "فاروس للتصميم" puts the words in the **wrong order** (فاروس on the left) and emits 4 extra zero-width glyphs per word, which puts TextEdit caret mapping at risk. · With Plex Sans Arabic first, "Artboard فاروس" becomes one Latin-guessed run: the Arabic word comes out **unjoined and left-to-right**. · So "chrome stays Latin for V1" does not keep Arabic out. Layer, artboard, file and recent-file names are user text shown in chrome.

(d) Glyph coverage: Plex Sans, Plex Mono and Plex Sans Arabic have none of ⌥ ⌃ ⌘ ⇧ ∠ ⋯ ⋮ ☰. Among egui's default fonts, ⌥ and ⌃ exist nowhere, ⌘ only in `emoji-icon-font`, ⇧ only in Hack. So `hint()` output ("⌥", "⌃") draws tofu in egui. U1's "hints read ⌘ ⌥ ⇧ on the Mac" cannot pass, and L30 forbids falling back to the OS font.
(e) IBM's npm packages ship WOFF/WOFF2 only. `skrifa`/`read-fonts` 0.39 read raw sfnt only, so the TTFs must come from the IBM/plex GitHub releases. TTF sizes: Plex Sans Regular 200,388 B · Plex Sans SemiBold 202,520 · Plex Mono Regular 172,976 · Plex Sans Arabic Regular 236,612 · Plex Sans Arabic SemiBold 245,448. The set is ≈0.81 MB, or 1.06 MB with the Arabic SemiBold.
(f) The OFL carries the Reserved Font Name "Plex". Any subset or modified file must be renamed.

*Change:* R2 → "egui 0.35 applies the font's default OpenType features (kerning, ligatures, Arabic joining) but no caller-chosen features and no bidi. Single-word Arabic renders correctly. Multi-word or mixed Latin/Arabic names render in the wrong order; this is a known V1 limitation, recorded by a golden of 4 fixed strings so an egui upgrade that fixes it is noticed. Arabic UI/bidi = its own spike." · Add to L30's test: "every character any `hint()`, `CommandSpec.label` or kit glyph can emit has a glyph in the installed families (`Fonts::has_glyphs`)". · Q2 gains: "modifier keys ⌘⌥⇧⌃ drawn as kit icons, not text" and "TTFs from the IBM/plex GitHub release; `assets/fonts/` records source URL, version and SHA-256 next to `OFL.txt`; no subsetting".

**F5 · P2 — Q3 bundles three decisions, and L28 misses egui's own motion.** `boxtree.rs:695` says the directional gradient is "exactly Ahmed's 07-05 model". Like the ghost lift and the fork's glide, it is an owner design, not only a law breach. The replacement ("flat azure outline") drops the direction cue that the gradient carries. There is a precedent: zoom easing was removed by owner decision (07-12, reaffirmed 09-23, `36d04d4`). Separately, egui animates things L28 does not cover: `Style::scroll_animation` defaults to 0.1–0.3 s for every `scroll_to_*` (for example, keeping Start/Layers keyboard focus in view), and `WheelState` smooths line-unit mouse wheels over ≈0.1 s (unconfigurable, `wheel_state.rs:161`).
*Change:* Split Q3 into Q3a (ghost ease + glide → cursor 1:1 and an instant dock, as with zoom), Q3b (gradient → flat ACCENT_TINT on the target **plus the existing `edge_bar`/`seam_bar`**, so the direction stays), and Q3c (splash hold). · Add to L28: "`style.scroll_animation = ScrollAnimation::none()`, asserted by the same test; egui's line-wheel smoothing is a named residual". · Replace L28's regex grep with a behavioural test: the ghost position equals the pointer within the same frame.

**F6 · P2 — Kit coverage: no component has only one use, but three used controls are missing.**

Missing: `switch` (`toggle_row`: Snapping ×3, Artboard ×4, Document ×2); `text_field` (Layers search, picker hex on stock `TextEdit`, `name_field`; `inline_edit` is its commit-on-change mode); `tab_chip` (S1-C doc chips, S2's Home chip, box pills `boxtree.rs:578`). Without these, L26's "panels paint controls only through kit components" is false on day one. No piece migrates S1-C/E2 painters: U0-D ships only `icon_button`/`button`/`separator`, while E2 (Start) needs `list_row`/`section`, which are born in U3.
*Change:* §3.3: add `switch`, `text_field` (with `inline_edit` as its mode) and `tab_chip`. · U0-D also ships `section` + `list_row` (both S), so E2 can use them. · Add to U6-A: "S1-C chips, Home chip, Start rows → kit". · Leave the picker rails and planes as content (exempt). Do not add the mockup's opacity slider until a home needs it.

**F7 · P2 — Goldens: the renderer choice is right, but the preconditions are unstated.** `egui::Context::run(RawInput) → FullOutput.shapes` is pure CPU, so it satisfies "no GPU Renderer in tests". `egui_kittest` image snapshots would need wgpu. The preconditions are:
`set_fonts` applies on the *next* pass, so testkit runs a warm-up pass with the bundled fonts. **U0-D therefore depends on U0-C and Q2.** Today U0's pieces run in parallel. · Shapes carry no widget key, so the kit must record key→rect through a testkit hook. · Colours drawn with alpha must print as `TOKEN×α` (for example `MUTED×0.4`), not as "unknown colour". · States need scripted input: a pointer move for hover, a press for pressed, `request_focus` for focus. · Run goldens at ppp 1 **and** 2, because the Retina bugs are the point. · Text goldens prove tokens and geometry, not looks.

*Change:* Add these six lines to §3.3's testkit paragraph. · Sequence U0-C → U0-D. · Add a **debug-only kit gallery** (one box showing every component × state; excluded from release by L34). Ahmed approves the kit look once, at U0/U2, before U3's six pieces multiply it.

**F8 · P2 — The focus look is defined incompletely.**
A "1 pt FOCUS outline inset" on an ACCENT-filled current tool is ACCENT on ACCENT (1.0:1), so it is invisible. · There is no rule that the ring appears only after keyboard navigation (focus-visible), so mouse clicks could leave azure rings everywhere. · `State` has 5 booleans, but precedence is undefined (on+hover, on+focus, disabled+focus), and "pressed" has no look (audit 02: "Pressed: none").

*Change:* §4 Keyboard focus → "Ring only after keyboard navigation. On an ACCENT fill the ring is ON_ACCENT, 1 pt inset. Precedence: disabled > on > pressed = hover > rest; focus is drawn on top." · Add goldens for on+hover, on+focus and disabled.

**F9 · P2 — L29's contrast test checks the wrong backgrounds.** It tests "on PANEL/SEAM", but MUTED fails 4.5:1 on HOVER (**4.28**) and on a selected row (ACCENT_TINT over PANEL, **4.36**).
*Change:* "…computes each text token against every fill a text can sit on: PANEL, SURFACE, HOVER, ROW_HOVER, INPUT_WELL, selected row, SEAM". Hovered and selected rows raise their text to TEXT through `look()`.

**F10 · P2 — Four copies of the token values contradict "Tokens live in ONE place" (CLAUDE.md).** The copies are `tokens.rs`, UI_DIRECTION prose ("~6px"), the mockup `:root` and U6-C's `DESKTOP_UI_STANDARD.md`, kept in sync by tests that parse Markdown prose and HTML. The mockup's `:root` has no seam, capsule or mark variables (the seam is `gap:6px;padding:6px` in `.mid`), its fonts are Segoe/Cascadia, and its own status line says "not current authority".
*Change:* §3.4 last paragraph → "`tokens.rs` is the only source of values. UI_DIRECTION and the standard doc each carry one fenced token table that a test regenerates from `tokens.rs` (`UPDATE_GOLDEN=1`) and compares. The mockup gets a banner 'layout illustration; values live in tokens.rs' and is not kept in sync."

**F11 · P2 — The token schema has gaps.**
Existing tokens it drops: `CLOSE_RED`, `NONE_RED`, `VOID_HOVER`, `NAVY/AMBER`, `ACCENT_HOVER`. `ACCENT_HOVER` has one user, the azure OK button that Q4 retires, so delete it explicitly. · There is no text colour for errors and warnings, which S3 §3.8 needs for "Recovery copy couldn't be saved". · `H_BOXHEAD`, `STATUS_H` and `TOOLTIP_DELAY` have no values. · `T_MICRO`'s weight 600 needs its own family (`varos-ui-semibold`, plus the Arabic SemiBold for fallback). L30's test names only `varos-ui`/`varos-mono`. · The SP scale has no 6, yet the mockup's `.frow`/`.ctlbar` gaps are 6. · Ruler numerals (mockup 8.5 mono) and the HUD (mono 10) have no type token. · "Platform sizes come from `Platform`, not tokens" contradicts L25.

*Change:* Add `DANGER` (contrast-tested) and keep the red/void tokens. · Put per-platform consts in `tokens.rs`, selected by `Platform`. · Give every token a value or "measured in Ux". · Either add `SP` 6 or state the 6→4/8 change in Q4.

**F12 · P2 — Binary economy.** `egui = "0.35"` keeps the `default_fonts` feature: Ubuntu-Light 361,676 + Hack 309,408 + NotoEmoji 418,804 + emoji-icon 324,132 ≈ **1.41 MB**, more than the whole Plex set. Only varos-app enables it: egui-wgpu, egui-winit and the fork all use `default-features = false`. Today it is the only source of ⌘ (`emoji-icon-font`) and of ⇧, ∠ and ⋯ (Hack).
*Change:* add to U0-C: "after ⌘⌥⇧⌃ ∠ ⋯ ⋮ are kit icons and the coverage test passes, `egui = { version = "0.35", default-features = false }`".

**F13 · P3 — Wording and overclaims.**
(a) Q4's "selected segment = ACCENT" means the canvas path-segment highlight (`SEG_HI`), but it reads as the kit's `segmented` control. → "selected path segment".
(b) L29's "every number in `T_NUM`" also catches "Untitled-1". → "every numeric value in a field, readout, HUD or ruler".
(c) U0's "Ahmed: … nothing moved" is not true: Plex's widths differ from Ubuntu-Light's, and there are fixed-width labels (the 22 px label column, `toggle_row(ui, 114.0, ..)`). → Add "headless no-overflow check of existing panels with the new fonts" to U0-C's evidence.
(d) The claim that a dead control cannot be written holds only for `Act`-taking components. `segmented`, `swatch`, `num_field` and `list_row` return values. → The L12 test walks the call sites of those four.
(e) Uppercasing for `T_MICRO` happens inside `section()`, so table labels stay in their natural case for later localisation.

## The whole spec, from this angle
1. **Laws.** L25–L30 are necessary and trace to findings. Sharpen L27 (F2), L28 (F5), L29 (F3, F9) and L30 (F4). No law needs deleting. L26 and L31 overlap on "no literals", which is fine because L31 is L26's gate.
2. **Simplest architecture.** One `look()`, text goldens and no `egui_kittest` are the minimal choices. The one over-built part is keeping four token copies in sync (F10). The one avoidable dependency is egui's default fonts (F12).
3. **Plan.** U0-D must follow U0-C (F7). QW6 is missing from the `tokens.rs` queue (F3). S1-C/E2 painters have no migration piece (F6).
4. **Decisions.** Q2 and Q4 are the right questions, but they rest on wrong or missing facts (F2, F3, F4). Q3 should be three questions (F5).
5. **What a world-class reviewer would add.** An RTL/bidi plan for user text before "Arabic-first" is claimed in chrome (F4c). Focus-visible semantics (F8). A single icon standard: one SVG set on a 24 grid with stroke 1.6, rasterised at ppp — today there are 4 icon systems (02-V-G4b), and U6 "closes" that without any rule. A user UI-scale setting (egui `zoom_factor`, nearly free) as the real answer to Astra F11. A kit gallery as the living spec (F7).

## Needs Ahmed (recommended default)
1. **Fonts (Q2).** Plex Sans Regular + SemiBold for the UI and Plex Mono for numbers, with Plex Sans Arabic after Plex Sans as a fallback. *Default: yes.* Arabic names with several words, or mixed Arabic and Latin, are known to render wrong until a bidi spike. ⌘⌥⇧⌃ are drawn as small icons. egui's default fonts (1.4 MB) are removed.
2. **Motion (Q3 split).** 3a: no glide and no easing — the ghost sticks to the mouse (default yes, as with zoom). 3b: the gradient becomes a flat wash while keeping the edge bar (default yes). 3c: the splash hold goes (default yes).
3. **"On" looks, all from the mockup.** Current tool = azure block. Toggle on = small azure bar under a bright icon. Chosen tab or segment = SURFACE fill, no azure. Switch on = azure track. HUD = dark panel, not azure. *Default: yes.*
4. **Labels.** FAINT becomes MUTED for all labels, the status bar and ruler numbers. Size and icon size = whatever he approves in QW6's hand test. *Default: yes, after QW6.*
5. **Kit gallery.** A debug-only box showing every control in every state, for one eye check before U3. *Default: yes.*
