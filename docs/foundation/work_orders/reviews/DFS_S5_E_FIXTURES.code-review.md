## Findings

1. **P3 — `corpus_check.rs` prints but never fails on refusal.** `varos-pdf/tests/corpus_check.rs:60-65`. If `refused > 0` it only prints a note; the test (and process exit code) still succeeds. Since this is meant to gate a merge, a stray copy-paste into a script (rather than a human reading `--nocapture` output) would silently report success. *Fix:* after the summary, `assert_eq!(refused, 0, "…files refused, see output above…")` (or a plain `panic!`) when `refused > 0`, so a scripted run also fails loudly. Not blocking — the current hand-test instructions already require sending the printed output.

2. **P3 — the `/VAROS_Model` half of the harness is not verbatim, contrary to the piece's literal wording.** `varos-pdf/tests/old_reader_harness.rs:48-55` vs `ecf67f5:varos/crates/varos-pdf/src/lib.rs:343-356`. The doc comment discloses this ("Test plumbing only … NOT part of the frozen gate under test"), and it's a reasonable simplification since the catalog key is unchanged since `b06194a` and only the version gate is being proven — but the work order (§4, S5-E) asked for "a ≤15-line verbatim copy … of the old `/VAROS_Model` lookup" too. *Fix (optional):* either replace `embedded_model_json` with an actual verbatim trim of `ecf67f5:lib.rs:343-356` (it already fits well under 15 lines), or amend the work order/README to record that only the version-gate half is claimed verbatim. No functional risk either way.

3. **P3 — small duplicated fixture-loading helpers.** `fixture()`/`load_fixture()`/`tmp()` in `varos-core/tests/golden.rs:22-33` are near-identical to the same three in `varos-pdf/tests/golden_pdf.rs:21-35` (different crate, different `load_vrs`). ~10 lines each, in separate test binaries in separate crates — not worth a shared test-support crate for this size. No action needed.

No P1/P2 findings. The implementer's report is accurate: 462/3 confirmed exactly, the two `#[ignore]` tests reproduce the claimed pre-S5-B failure verbatim, and the 16-fixture corpus is genuinely content-equal round-trip on both raw and PDF paths.
