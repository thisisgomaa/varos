## 1. Goal & acceptance

**S2 — recent files + Start.** One app-data resolver; atomic `recent.json`/`settings.json`; 20-item deduplicated Recent; Locate…/Remove for missing files; Home (Start) state when no document is open and via a Home chip while documents stay open; keyboard/focus states.
**S3 — durable writes + autosave/recovery.** App-owned durable replacement writer for the real `.vrs` save; recovery snapshots written separately (model-only JSON, two generations, manifest last) by one background I/O thread; 30 s scheduler; launch-time orphan scan; Recover (as a copy) / Discard (confirmed) / Later; visible status and failure.

Ahmed hand-tests (on the Mac, after both wave-2 pieces land — batch policy per STATUS):
1. Launch → Start (title "Varos", New document / Open…, RECENT). New → boardless canvas (A8a). Save, open another file, quit, relaunch → each file appears **once** in Recent, newest first.
2. Move a recent file in Finder → click it → "can't be found" → Locate… picks it → opens, entry updated. Cancel changes nothing. Remove from Recent / Clear Recent leave the files on disk.
3. Close the last tab (clean) → Start. Home chip with two tabs open → Start; clicking a tab returns to its canvas unchanged (zoom, selection, not dirty).
4. Edit two documents (one untitled), wait until the status says "Recovery copy saved …", force-quit (`kill -9` / Activity Monitor), relaunch → banner "Varos closed unexpectedly…" → Review Recovery → both listed with name, original location, time → Recover both → each opens as "<name> (Recovered)", dirty, pathless; originals on disk unchanged (compare bytes/mtime); Save As proposes `<name>-recovered.vrs`.
5. Later keeps the offer for next launch; Discard asks "Discard recovery copy of …?" (Cancel default). Turn Recovery off in the Document home → "Recovery is off…" note; existing copies remain. Launch with `VAROS_DATA_DIR` pointing at a read-only folder → "Recovery unavailable", editing still works.
6. Damage the newest `snap-*.json` of a session (truncate it) → Recover falls back to the previous generation and says so.

Headless tests prove: resolver per OS; atomic write fault matrix (fail at create / write / sync / rename / dir-sync; disk full; read-only destination) keeps the old file byte-identical; recents dedupe/cap/locate/never-pollute; manifest-last publication, two generations, corrupt-newest fallback, orphan vs live-owner detection, retire/tombstone cleanup; scheduler timing (30 s, no reset per edit, gesture deferral, one in-flight per session, out-of-order completions, backoff, disabled mode); Start view-model (rows, middle elision, empty copy, key gating). No test builds a Renderer or EventLoop.

## 3. Design

### 3.1 Seam
Everything here is `varos-app` (spec §3 owner table). Core gains at most one read-only probe (`Editor::in_transaction`, if S1 does not add it). `varos-pdf` unchanged (`write_pdf` bytes reused). No new workspace crate, no dependency-edge change (ADR-0005). One direct dependency: `chrono = { version = "0.4", default-features = false, features = ["clock"] }` in `varos-app` for the spec's "saved at 14:32" local time (already compiled via lopdf; moderator approves in review — fallback §6 item 5).

New lib module tree `varos-app/src/storage/` (declared from `lib.rs` as `pub mod storage;`): `paths.rs`, `durable.rs`, `checksum.rs`, `time_text.rs`, `recents.rs`, `settings.rs`, `recovery.rs`, `scheduler.rs`, `io_worker.rs`. Test-only helper `storage/testdir.rs` (`#[cfg(test)]`, unique dir under `temp_dir()`, removed on `Drop`).

### 3.2 Data root (`paths.rs`)
`resolve_data_root(os: Os, env: &dyn Fn(&str) -> Option<OsString>, home: Option<PathBuf>) -> Option<PathBuf>` (pure; `Os::{Mac, Windows, Linux}`), plus `data_root() -> Option<PathBuf>` using the real env and `std::env::home_dir()`.
Order: `VAROS_DATA_DIR` override (tests + the unwritable-storage hand test) → macOS `~/Library/Application Support/Varos` → Windows `%APPDATA%\Varos` (today's location, so the existing `window.txt` keeps working) → Linux `$XDG_DATA_HOME/varos` else `~/.local/share/varos`. Relative values are rejected; **never** the working directory; `None` ⇒ "Recovery unavailable" and Recent kept in memory only.
`AppLayout { root }` with `window_state() = root/window.txt`, `crash_log() = root/Logs/crash.txt`, `recents() = root/recent.json`, `settings() = root/settings.json`, `recovery() = root/Recovery`. `main.rs` `win_state_path`/`crash_log_path` delegate to it; **`win_state_path` stays `None` on macOS** (window memory on Mac is separate Mac polish — no behaviour change here), while the crash log starts working on Mac.

### 3.3 Durable replacement writer (`durable.rs`)
Port (fault injection): `trait FsPort: Send + Sync { create_new(&Path) -> io::Result<Box<dyn SyncWrite>>; rename(&Path,&Path); sync_dir(&Path); remove_file(&Path); read(&Path) -> io::Result<Vec<u8>>; metadata(&Path) -> io::Result<FileMeta>; create_dir_all(&Path); read_dir(&Path) -> io::Result<Vec<PathBuf>> }`, `trait SyncWrite: Write { fn sync_all(&mut self) -> io::Result<()>; }`. `RealFs` = std. `FaultFs { inner: RealFs, plan: Mutex<Vec<Fault>> }` with `Fault { step: Step::{Create, Write{after: usize}, Sync, Rename, SyncDir, Remove}, path_contains: Option<String>, kind: io::ErrorKind }` — lives in the lib (not `cfg(test)`) so wave-2 app tests can use it.
`pub fn write_replace(fs: &dyn FsPort, dest: &Path, bytes: &[u8], nonce: &str) -> Result<WriteOutcome, WriteError>`:
1. Resolve a symlinked `dest` to its target; refuse a read-only destination (`WriteError::ReadOnly`) instead of renaming over it; missing parent → `WriteError::Folder`.
2. Temp = same directory, `.{file_name}.{nonce}.varos-tmp` (hidden on macOS), `create_new` (O_EXCL) — unique per write, never the fixed `.vrs.tmp`.
3. `write_all` → `sync_all` (std on Apple targets issues `fcntl(F_FULLFSYNC)`; the implementer cites the std source line in the PR) → drop → copy the existing destination's permissions onto the temp.
4. `rename(temp, dest)` — POSIX `rename(2)` is an atomic replace; on Windows `std::fs::rename` replaces an existing file (MoveFileEx/FileRenameInfoEx replace semantics); a sharing violation (file open in a PDF viewer) fails **before** replacement.
5. Unix: `sync_dir(parent)`; `Unsupported/InvalidInput` from the directory sync counts as durable (documented); another error ⇒ `Ok(WriteOutcome::ReplacedUnconfirmed(err))`. Windows: no directory sync (not supported), `Durable`.
6. Any failure before step 4: best-effort `remove_file(temp)`, destination untouched, `Err`. The destination is never deleted first.
`WriteError::{Folder, ReadOnly, Create(io::Error), Write(io::Error), Sync(io::Error), Replace(io::Error)}` with `fn reason(&self) -> String` (plain English, used as `{reason}` in the spec copy): StorageFull → "The disk is full."; PermissionDenied/ReadOnlyFilesystem → "Varos isn't allowed to write there."; Windows sharing violation (raw 32/33) → "The file is open in another app."; else the OS text.
Also `pub fn fingerprint(fs, path) -> Option<Fingerprint { len: u64, modified: Option<SystemTime> }>` for the external-change check (§3.8). `checksum.rs`: in-house CRC-32/IEEE (`crc32(&[u8]) -> u32`, test vector `"123456789"` → `0xCBF43926`); `new_nonce() -> String` = 128 bits hex from `RandomState`-seeded hashing of time + pid + counter (unique, not secret).

### 3.4 Recents + settings (`recents.rs`, `settings.rs`)
`RecentEntry { path: PathBuf, name: String, last_opened: u64 /* unix s */, #[serde(default)] file_id: Option<(u64, u64)> /* unix dev+ino */ }`; `Recents { entries: Vec<RecentEntry> }` newest first, `MAX = 20`. On disk `{"version":1,"items":[…]}`.
`pub enum FileEvent { Opened(PathBuf), Saved(PathBuf), OpenFailed(PathBuf), SaveFailed(PathBuf), Exported(PathBuf), Snapshot(PathBuf) }`; `Recents::observe(&mut self, ev: &FileEvent, id: Option<(u64,u64)>, now: u64) -> bool /* changed */` — **only** `Opened`/`Saved` record; the coordinator forwards every event, so "failures/exports/snapshots never pollute Recent" is a property of this pure function. Dedupe key: `normalize(path)` (absolute + lexical clean; case-folded on macOS/Windows) **or** equal `file_id` when both known. Also `remove(&Path)`, `clear()`, `relocate(old, new, id, now)` (called only after Locate's open succeeded), `entries()`.
`load(fs, path) -> (Recents, Option<String> /* warning */)`: missing → empty; corrupt/unknown version → empty + warning, corrupt file renamed `recent.json.bad` (never silently overwritten on first read). `save(&self, fs, path)` = `serde_json` → `durable::write_replace`. Writes are rare and small → synchronous on the UI thread in S2; if Mac measurement shows >50 ms, F1 routes them through the I/O worker.
`Settings { version: 1, recovery_enabled: bool /* default true */ }`, same load/save contract (`settings.json`). Missing-file status is computed at draw time with a cached `exists` probe refreshed when Start is shown (not per frame).

### 3.5 Recovery store (`recovery.rs`)
Layout `Recovery/owners/<owner>.lock` and `Recovery/<rid>/{manifest.json, snap-<seq>.json, retired, claim.lock}` (`rid` = nonce, per session; `owner` = nonce, per process).
`Manifest { manifest_version: 1, owner, rid, display_name, untitled_number: Option<u32>, original_path: Option<PathBuf>, source_fingerprint: Option<Fingerprint>, recovered: bool, model_version: u32 /* VRS_VERSION */, created: u64, generations: Vec<Generation> }`, `Generation { seq: u64, file: String, bytes: u64, crc32: u32, saved_at: u64 }` (newest first, ≤ 2). The blob is exactly `varos_core::file::doc_to_blob(doc)` bytes (model only, no PDF), so recovery decodes through the same function Open uses (`doc_from_blob`, replaced by S5's validated pipeline when it lands).
API (bytes-level; no `Document` inside the store):
```rust
impl RecoveryStore {
  pub fn open(fs: Arc<dyn FsPort>, recovery_dir: PathBuf) -> Result<Self, SnapError>; // mkdir + take owner lock (File::try_lock) for process life
  pub fn owner(&self) -> &str;
  pub fn write_generation(&self, meta: &SessionMeta, seq: u64, blob: &[u8], now: u64) -> Result<Generation, SnapError>;
  pub fn retire(&self, rid: &str) -> Result<(), SnapError>;          // create `retired` first, then delete files, then dir
  pub fn scan(&self) -> Vec<OrphanEntry>;                              // dead owner ⇒ orphan; live owner (lock held) skipped
  pub fn claim(&self, rid: &str) -> Result<ClaimGuard, SnapError>;     // try_lock claim.lock; Busy if another process reviews it
  pub fn load_best(&self, rid: &str) -> Result<Loaded { blob: Vec<u8>, generation: Generation, fell_back: bool }, SnapError>;
  pub fn adopt(&self, claim: &ClaimGuard, meta: &SessionMeta) -> Result<(), SnapError>; // rewrite manifest: owner = me, recovered = true
  pub fn cleanup_completed(&self);                                      // dirs with `retired`, stale owner locks, orphan temp files
}
pub struct SessionMeta { pub rid: String, pub display_name: String, pub untitled_number: Option<u32>, pub original_path: Option<PathBuf>, pub source_fingerprint: Option<Fingerprint>, pub recovered: bool }
pub struct OrphanEntry { pub rid: String, pub display_name: String, pub original_path: Option<PathBuf>, pub saved_at: Option<u64>, pub state: OrphanState /* Ready | Damaged(String) | NewerFormat(u32) */ }
```
`write_generation` order: blob → `durable::write_replace(snap-<seq>.json)` → manifest (new generation first, keep previous) → `write_replace(manifest.json)` (**manifest published last**) → delete generations older than N-1. A failure at any step leaves the previous manifest and both of its generations intact (a new blob never overwrites a listed file because `seq` is new). `load_best`: newest generation whose size + CRC match and whose JSON head parses; else the previous (`fell_back = true`); manifest unreadable ⇒ scan `snap-*.json` newest-first (metadata "unknown"). Damaged/unsupported entries are **kept** with a reason, never age-deleted; only `retire` (explicit Discard, Don't Save, clean save) or a `retired` tombstone removes data. The original document file is never touched by this module (it only writes under `Recovery/`). Snapshot size cap `MAX_SNAPSHOT_BYTES = 32 MiB` (spec's provisional model limit; S5 may change it) ⇒ `SnapError::TooLarge` with a visible warning.

### 3.6 Scheduler + I/O thread (`scheduler.rs`, `io_worker.rs`)
Decision: **a single background I/O thread** plus a **pure scheduler on the main loop**. Serializing, CRC, `F_FULLFSYNC` and renames can take tens of ms on a Mac and scale with document size, so they cannot run inside `AboutToWait`. The only UI-thread cost is one `Document` clone at a settled boundary (the same cost as every `Editor::begin()`); F1 measures it on the large perf-harness scene and records the number.
`Scheduler::new(interval = 30 s)`, all time injected (`now: Instant`):
- `observe(&mut self, now, probes: &[Probe]) -> Vec<Action>` with `Probe { sid: SessionKey, rid: &str, checkpoint: u64 /* S1 content checkpoint, Eq only */, clean: bool, in_transaction: bool }` and `Action::{Snapshot { sid, seq }, Retire { sid }, Waiting { sid } }`.
- Rules: first observed content change since the last successful snapshot starts `deadline = now + 30 s`; later edits **do not** move it. At the deadline: `in_transaction` ⇒ `Waiting` (UI: "Recovery waiting for edit to finish"); otherwise one `Snapshot` if none is in flight for that session (one job per session). `clean` (content equals saved checkpoint) ⇒ no snapshot, and `Retire` if snapshots exist. Disabled ⇒ no actions (existing copies stay).
- `on_complete(&mut self, now, Completion { sid, seq, checkpoint, result })`: ignores a completion whose `seq` is older than the newest applied (out-of-order safe); success records checkpoint + time and re-arms at `issued_at + 30 s` if content moved on; failure keeps the previous generation, exposes the error, retries at `now + 30 s` (Retry button = immediate).
- `next_wake(&self) -> Option<Instant>` ⇒ main loop sets `ControlFlow::WaitUntil(min)` in `AboutToWait`, else `Wait`.
`IoWorker::spawn(store: RecoveryStore, wake: Box<dyn Fn() + Send>)`; `submit(Job::{Snapshot { sid, seq, checkpoint, meta, doc: Document }, Retire { sid, rid }})`; `try_completions() -> Vec<Completion>`; `shutdown(self)` drains the queue then joins (quit path: all retires finish before exit). FIFO on one thread = writes serialized per destination. `wake` is an `EventLoopProxy<()>::send_event(())` closure in `main.rs`, a counter in tests. The worker never touches an `Editor`.

### 3.8 Recovery UX + real-file save integration (wave 2)
- Launch: `RecoveryStore::open` + `cleanup_completed` + `scan`. Orphans ⇒ Start's Recovery section (the one home) and, when a file intent skipped Start, a one-line SEAM strip below the app bar: **Varos closed unexpectedly. Recovery copies are available.** / "Review copies from your last session before continuing." / **Review Recovery · Later** (Review = show Start). Store failure ⇒ status "Recovery unavailable" (no fallback directory).
- Recover: `claim` → `load_best` → `doc_from_blob` (+ size cap) → new session, dirty, pathless, named `<name> (Recovered)` → `adopt` (the session keeps writing into the same `rid`; generation N-1 still holds the source until superseded) → strip **Recovered “{name}” from {time}.** / "Save this copy to keep it. Your original file has not been changed." / **Save As…**; `fell_back` adds "The newest copy was damaged; the previous copy was used." Save As default `<name>-recovered.vrs` in the original folder. Failure stays in the list with its reason.
- Discard: **Discard recovery copy of “{name}”?** / "Unsaved changes in this copy will be lost." / **Discard · Cancel** (Cancel default) → `retire`. Later: hide the strip for this run; next launch offers again.
- Retirement: clean after explicit Save/undo-to-saved ⇒ `Retire`; newer edits keep protecting. Don't Save ⇒ retire after the close commits. Successful Save As of a recovered session ⇒ clean ⇒ retire. Normal quit ⇒ every session retired, `IoWorker::shutdown` drains.
- Status (mirror in the status bar; home = Document section from S1): "Saving recovery copy…", "Recovery copy saved at 14:32", "Recovery waiting for edit to finish", failure **Recovery copy couldn't be saved. Save your document now.** **Retry · Save…**; off: **Recovery is off. Save regularly to keep your work.** Document home gets the Recovery on/off switch (app-wide setting, persisted in `settings.json`) and "Last recovery copy: 14:32 · <folder>".
- Real Save: S1's save path writes `varos_pdf::write_pdf(&doc)` bytes via `durable::write_replace` (still synchronous on the UI thread — the user is waiting on an explicit command; async Save is §6 item 6). `ReplacedUnconfirmed` ⇒ path updated but checkpoint not advanced + message "Saved, but Varos couldn't confirm the disk finished writing. Your recovery copy is kept." Before overwriting, compare `fingerprint` with the one captured at open/last save; changed/deleted ⇒ **“{name}” was changed by another app.** / "Saving now would replace those changes." / **Save As… · Replace Anyway… · Cancel** (Replace asks once more). After a successful save, delete stale `.{name}.*.varos-tmp` siblings of that exact file.

## 6. Risks / open questions (each with a default so execution never blocks)
1. **S1 API drift** (empty workspace, outcome hooks, checkpoint, recovered-session constructor). Default: wave-2 pieces adapt to S1's real names; the §3.9 list is the checklist the moderator ticks before starting E/F1/F2.
2. **Durability is platform-specific and Linux CI cannot prove it.** `F_FULLFSYNC`, directory sync on APFS, Windows sharing violations are verified by reading std source + Mac hand test (§1 step 4/6), not by CI. Default: honest `WriteOutcome` + Mac-only hand evidence; Windows stays compile-only (STATUS).
3. **UI-thread clone cost / event-loop pauses.** A `Document` clone per snapshot on huge files, and macOS modal dialogs or live resize pausing `AboutToWait`. Default: measure clone time on perf-harness scene B at 10× and log it in GATE_LOG; a paused loop only delays the next snapshot (no data race — the worker keeps finishing jobs).
4. **Start needs an editor-free UI path** in a 6 000-line editor-bound `ui.rs`. Default: `Ui::run_home` (S1-9) instead of threading `Option<&mut Editor>` through every panel.
5. **Q1 Local clock text** needs a time-zone source. Default: direct `chrono` (clock) dep, zero new crates in the lock. Fallback if rejected: relative text ("saved 2 min ago") from `time_text::relative`.
6. **Q2 Async real Save** (spec §3 "Save I/O off the UI thread"). Default: S3 keeps Save synchronous through the durable writer; move it onto the I/O worker in S6 if a 10 MB save measures >100 ms on the Mac.
7. **Q3 Recovered-session identity:** adopting the orphan's directory (not copying it). Default: adopt — the source stays as generation N-1 until two newer copies exist, and a second crash still leaves the newest content recoverable.
8. **Q4 Mac window memory** now possible through the resolver. Default: stay disabled on macOS in this stage (separate Mac-polish item); crash log enabled.
9. **Q5 Settings location of the Recovery switch:** spec puts it in the Document home though it is app-wide. Default: follow the spec; the label says "for all documents".
10. **Q6 Stale hidden temp files** in user folders after a crash mid-save. Default: remove exact-pattern siblings after the next successful save of that file; never scan other folders.
11. Autosave is not the real file: a crash can lose edits made after the last completed snapshot (≤ ~30 s + write time). All copy says "recovery copy", never "saved"; the dirty dot never clears from a snapshot.
