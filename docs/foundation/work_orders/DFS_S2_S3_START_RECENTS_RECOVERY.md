## 1. Goal & acceptance

**S2 — recent files + Start.** One app-data resolver; atomic `recent.json`/`settings.json`; 20-item deduplicated Recent; Locate…/Remove for missing files; Home (Start) state when no document is open and via a Home chip while documents stay open; keyboard/focus states.
**S3 — durable writes + autosave/recovery.** App-owned durable replacement writer for the real `.vrs` save; recovery snapshots written separately (model-only JSON, two generations, manifest last) by one background I/O thread; 30 s scheduler; launch-time orphan scan; Recover (as a copy) / Discard (confirmed) / Later; visible status and failure.

Ahmed hand-tests (on the Mac, after both wave-2 pieces land — batch policy per STATUS):
1. Launch → Start (title "Varos", New document / Open…, RECENT). New → boardless canvas (A8a). Save, open another file, quit, relaunch → each file appears **once** in Recent, newest first.
2. Move a recent file in Finder → click it → "can't be found" → Locate… picks it → opens, entry updated. Cancel changes nothing. Remove from Recent / Clear Recent leave the files on disk.
3. Close the last tab (clean) → Start. Home chip with two tabs open → Start; clicking a tab returns to its canvas unchanged (zoom, selection, not dirty).
4. Edit two documents (one untitled), wait until the status says "Recovery copy saved …", force-quit with `kill -9 $(pgrep varos)`, relaunch → banner "Varos closed unexpectedly…" → Review Recovery → both listed with name, original location, time → Recover both → each opens as "<name> (Recovered)", dirty, pathless; originals unchanged (Finder ▸ Get Info ▸ Modified unchanged); Save As proposes `<name>-recovered.vrs`.
5. Later keeps the offer for next launch; Discard asks "Discard recovery copy of …?" (Cancel default). Turn Recovery off in the Document home → "Recovery is off…" note; existing copies remain. Launch with `VAROS_DATA_DIR=/tmp/ro /Applications/Varos.app/Contents/MacOS/varos` (a read-only folder) → "Recovery unavailable", editing still works.
6. Damage the newest `snap-*.json` of a session: `: > "$HOME/Library/Application Support/Varos/Recovery/<rid>/snap-N.json"` (truncate it) → Recover falls back to the previous generation and says so.

Headless tests prove: resolver per OS; atomic write fault matrix (fail at create / write / sync / rename / dir-sync; disk full; read-only destination) keeps the old file byte-identical; recents dedupe/cap/locate/never-pollute; manifest-last publication, two generations, corrupt-newest fallback, orphan vs live-owner detection, retire/tombstone cleanup; scheduler timing (30 s, no reset per edit, gesture deferral, one in-flight per session, out-of-order completions, backoff, disabled mode); Start view-model (rows, middle elision, empty copy, key gating). No test builds a Renderer or EventLoop.

### 3.2 Data root (`paths.rs`)
`resolve_data_root(os: Os, env: &dyn Fn(&str) -> Option<OsString>, home: Option<PathBuf>) -> Option<PathBuf>` (pure; `Os::{Mac, Windows, Linux}`), plus `data_root() -> Option<PathBuf>` using the real env and `std::env::home_dir()`.
Order: `VAROS_DATA_DIR` override (tests + the unwritable-storage hand test) → macOS `~/Library/Application Support/Varos` → Windows `%APPDATA%\Varos` (today's location, so the existing `window.txt` keeps working) → Linux `$XDG_DATA_HOME/varos` else `~/.local/share/varos`. Relative values are rejected; **never** the working directory; `None` ⇒ "Recovery unavailable" and Recent kept in memory only.
`AppLayout { root }` with `window_state() = root/window.txt`, `crash_log() = root/Logs/crash.txt`, `recents() = root/recent.json`, `settings() = root/settings.json`, `recovery() = root/Recovery`. `main.rs` `win_state_path`/`crash_log_path` delegate to it; **`win_state_path` stays `None` on macOS** (window memory on Mac is separate Mac polish — no behaviour change here), while the crash log starts working on Mac.

**Frozen for other work orders:** `varos_app::storage::paths::{data_root() -> Option<PathBuf>, AppLayout}` is the ONLY data-folder resolver; every other work order refers to it by this name. QUICK_WINS QW2 is dropped — it would have built a second `app_paths.rs::data_dir_from` and turned Mac window memory on, both superseded by A. Mac window memory stays off in this stage (§6 item 8) and becomes a small follow-up after S2/S3-A. S4-C and S6-B call `storage::paths::data_root()`.

### 3.3 Durable replacement writer (`durable.rs`)
Port (fault injection): `trait FsPort: Send + Sync { create_new(&Path) -> io::Result<Box<dyn SyncWrite>>; rename(&Path,&Path); sync_dir(&Path); remove_file(&Path); read(&Path) -> io::Result<Vec<u8>>; metadata(&Path) -> io::Result<FileMeta>; create_dir_all(&Path); read_dir(&Path) -> io::Result<Vec<PathBuf>> }`, `trait SyncWrite: Write { fn sync_all(&mut self) -> io::Result<()>; }`. `RealFs` = std. `FaultFs { inner: RealFs, plan: Mutex<Vec<Fault>> }` with `Fault { step: Step::{Create, Write{after: usize}, Sync, Rename, SyncDir, Remove}, path_contains: Option<String>, kind: io::ErrorKind }` — lives in the lib (not `cfg(test)`) so wave-2 app tests can use it. `FsPort` is frozen once A lands with the methods it actually needs (cloud tests run as root, so real permission faults and disk-full can't be produced otherwise — that already justifies it growing past this list): no new methods without moderator sign-off.
`pub fn write_replace(fs: &dyn FsPort, dest: &Path, bytes: &[u8], nonce: &str) -> Result<WriteOutcome, WriteError>`:
1. Resolve a symlinked `dest` to its target; refuse a read-only destination (`WriteError::ReadOnly`) instead of renaming over it; missing parent → `WriteError::Folder`.
2. Temp = same directory, `.{file_name}.{nonce}.varos-tmp` (hidden on macOS), `create_new` (O_EXCL) — unique per write, never the fixed `.vrs.tmp`.
3. `write_all` → `sync_all`. On Apple, if `F_FULLFSYNC` fails with ENOTSUP/ENOTTY/EINVAL, retry with plain `libc::fsync` (some non-local filesystems don't support full-sync, matching SQLite's `full_fsync` fallback in `os_unix.c`; needs a macOS-only direct `libc = "0.2"`, already in `Cargo.lock` through winit/objc2, so zero new crates — the same helper serves `sync_dir`) → drop → copy the existing destination's permissions onto the temp. Mac hand check: save to a USB stick or SMB share. Also cap the temp file's name part: `temp_path` adds ~45 bytes to the file name, so an uncapped name over ~210 bytes hits ENAMETOOLONG.
4. `rename(temp, dest)` — POSIX `rename(2)` is an atomic replace; on Windows `std::fs::rename` replaces an existing file (MoveFileEx/FileRenameInfoEx replace semantics); a sharing violation (file open in a PDF viewer) fails **before** replacement.
5. Unix: `sync_dir(parent)`; `Unsupported/InvalidInput` from the directory sync counts as durable (documented); another error ⇒ `Ok(WriteOutcome::ReplacedUnconfirmed(err))`. Windows: no directory sync (not supported), `Durable`.
6. Any failure before step 4: best-effort `remove_file(temp)`, destination untouched, `Err`. The destination is never deleted first.
`WriteError::{Folder, ReadOnly, Create(io::Error), Write(io::Error), Sync(io::Error), Replace(io::Error)}` with `fn reason(&self) -> String` (plain English, used as `{reason}` in the spec copy): StorageFull → "The disk is full."; PermissionDenied/ReadOnlyFilesystem → "Varos isn't allowed to write there."; Windows sharing violation (raw 32/33) → "The file is open in another app."; else the OS text.
Also `pub fn fingerprint(fs, path) -> Option<Fingerprint { len: u64, modified: Option<SystemTime> }>` for the external-change check (§3.8). `checksum.rs`: in-house CRC-32/IEEE (`crc32(&[u8]) -> u32`, test vector `"123456789"` → `0xCBF43926`); `new_nonce() -> String` = 128 bits hex from `RandomState`-seeded hashing of time + pid + counter (unique, not secret).

### 3.4 Recents + settings (`recents.rs`, `settings.rs`)
`RecentEntry { path: PathBuf, name: String, last_opened: u64 /* unix s */, #[serde(default)] file_id: Option<(u64, u64)> /* unix dev+ino */ }`; `Recents { entries: Vec<RecentEntry> }` newest first, `MAX = 20`. On disk `{"version":1,"items":[…]}`.
`Recents::record(&mut self, path: &Path, file_id: Option<(u64,u64)>, now: u64) -> bool /* changed */`, called only at the Opened/Saved sites (no `FileEvent` enum: it would have one caller and "prove" a property the caller can bypass — the integration tests already prove "never pollute Recent", see E `failed_open_leaves_recents…` and S6 `export_success_leaves_…recents_unchanged`). Dedupe key: equal `dev_ino` when both are known, else exact path equality — the caller passes S1's `DocStore::key(path)` values, so this module does not re-derive file identity (a second `normalize`/case-fold would be wrong on case-sensitive APFS and would ignore NFD names). Also `remove(&Path)`, `clear()`, `relocate(old, new, id, now)` (called only after Locate's open succeeded), `entries()`.
`load(fs, path) -> (Recents, Option<String> /* warning */)`: missing → empty; corrupt/unknown version → empty + warning, corrupt file renamed `recent.json.bad` (never silently overwritten on first read). `save(&self, fs, path)` = `serde_json` → `durable::write_replace`. Writes are rare and small → synchronous on the UI thread in S2; if Mac measurement shows >50 ms, F1 routes them through the I/O worker.
`Settings { version: 1, recovery_enabled: bool /* default true */ }`, same load/save contract (`settings.json`). Missing-file status is computed at draw time with a cached `exists` probe refreshed when Start is shown (not per frame).

### 3.5 Recovery store (`recovery.rs`)
Layout `Recovery/<rid>/{session.lock, manifest.json, snap-<seq>.json}` (`rid` = nonce, per session; one lock, not three — the spec asks only for "per-process/session ownership locks", so `owner.lock`/`claim.lock`/`adopt` are cut: the live session holds `session.lock` (`try_lock` when the dir is created); `scan` try-locks each dir, and success means an orphan **already claimed** by this process; Recover keeps the lock, and later `write_generation` calls rewrite the manifest meta, so no separate adopt step exists; std `try_lock` on Unix is `flock`, which conflicts between two opens inside one process, so "two stores in one process" tests still work).
`Manifest { manifest_version: 1, rid, display_name, untitled_number: Option<u32>, original_path: Option<PathBuf>, source_fingerprint: Option<Fingerprint>, recovered: bool, model_version: u32 /* VRS_VERSION */, created: u64, generations: Vec<Generation> }`, `Generation { seq: u64, file: String, bytes: u64, crc32: u32, saved_at: u64 }` (newest first, ≤ 2). The blob is exactly `varos_core::file::doc_to_blob(doc)` bytes (model only, no PDF), so recovery decodes through the same function Open uses (`doc_from_blob`, replaced by S5's validated pipeline when it lands).
API (bytes-level; no `Document` inside the store):
```rust
impl RecoveryStore {
  pub fn open(fs: Arc<dyn FsPort>, recovery_dir: PathBuf) -> Result<Self, SnapError>; // mkdir + take this session's lock (File::try_lock) for process life
  pub fn write_generation(&self, meta: &SessionMeta, seq: u64, blob: &[u8], now: u64) -> Result<Generation, SnapError>;
  pub fn retire(&self, rid: &str) -> Result<(), SnapError>;          // atomic rename(<rid>, <rid>.discarded-<nonce>), then best-effort remove_dir_all; the session then takes a fresh rid
  pub fn scan(&self) -> Vec<OrphanEntry>;                              // try-locks each dir; a lock taken here IS the claim; a live session's dir (lock held elsewhere) is skipped
  pub fn load_best(&self, rid: &str) -> Result<Loaded { blob: Vec<u8>, generation: Generation, fell_back: bool }, SnapError>;
  pub fn cleanup_completed(&self);                                      // removes `*.discarded-*` dirs left by an interrupted retire
}
pub struct SessionMeta { pub rid: String, pub display_name: String, pub untitled_number: Option<u32>, pub original_path: Option<PathBuf>, pub source_fingerprint: Option<Fingerprint>, pub recovered: bool }
pub struct OrphanEntry { pub rid: String, pub display_name: String, pub original_path: Option<PathBuf>, pub saved_at: Option<u64>, pub state: OrphanState /* Ready | Damaged(String) | NewerFormat(u32) */ }
```
`write_generation` order: blob → `durable::write_replace(snap-<seq>.json)` → manifest (new generation first, keep previous) → `write_replace(manifest.json)` (**manifest published last**) → delete generations older than N-1. A failure at any step leaves the previous manifest and both of its generations intact (a new blob never overwrites a listed file because `seq` is new). `load_best`: newest generation whose size + CRC match and whose JSON head parses; else the previous (`fell_back = true`); manifest unreadable ⇒ `OrphanState::Damaged(reason)`, kept (no blob-scan fallback — the spec asks only for a visible fallback from a corrupt newest generation, and the manifest is already written through `write_replace`). Damaged/unsupported entries are **kept** with a reason, never age-deleted; only `retire` (explicit Discard, Don't Save, clean save) or a `.discarded-<nonce>` tombstone removes data. The original document file is never touched by this module (it only writes under `Recovery/`). Snapshot size cap `MAX_SNAPSHOT_BYTES = 32 MiB` (spec's provisional model limit; S5 may change it) ⇒ `SnapError::TooLarge` with a visible warning.

### 3.6 Scheduler + I/O thread (`scheduler.rs`, `io_worker.rs`)
Decision: **a single background I/O thread** plus a **pure scheduler on the main loop**. Serializing, CRC, `F_FULLFSYNC` and renames can take tens of ms on a Mac and scale with document size, so they cannot run inside `AboutToWait`. The only UI-thread cost is one `Document` clone at a settled boundary (the same cost as every `Editor::begin()`); F1 measures it on the large perf-harness scene and records the number.
`Scheduler::new(interval = 30 s)`, all time injected (`now: Instant`):
- `observe(&mut self, now, probes: &[Probe]) -> Vec<Action>` with `Probe { sid: SessionKey, rid: &str, checkpoint: u64 /* S1's editor.rev — a change signal, Eq only */, clean: bool /* !session.is_dirty() */, in_transaction: bool /* S1's editor.transaction_open() */ }` and `Action::{Snapshot { sid, seq }, Retire { sid }, Waiting { sid } }`.
- Rules: first observed content change since the last successful snapshot starts `deadline = now + 30 s`; later edits **do not** move it. At the deadline: `in_transaction` ⇒ `Waiting` (UI: "Recovery waiting for edit to finish"); otherwise one `Snapshot` if none is in flight for that session (one job per session). `clean` (`!session.is_dirty()`) ⇒ no snapshot, and `Retire` if snapshots exist. Disabled ⇒ no actions (existing copies stay).
- `on_complete(&mut self, sid, now, Completion { sid, seq, checkpoint, result })` (review fix `cce22e6`: the owning session's `sid` is passed and a completion whose `sid` differs is ignored; while a Retire is in flight a new dirty revision sets `next_deadline = now + 30 s` and that deadline survives the Retire's completion; generation `seq` is bounded by `MAX_GENERATION_SEQ = 2^53` — larger manifests are damaged, writes beyond it are refused, increments saturate): ignores a completion whose `seq` is older than the newest applied (out-of-order safe, though unreachable with one-in-flight + FIFO — kept because the spec lists it); success records `checkpoint` (= the `rev` at issue time) + time and re-arms at `issued_at + 30 s` if `rev` moved on; failure keeps the previous generation, exposes the error, retries at `now + 30 s` (Retry button = immediate).
- `next_wake(&self) -> Option<Instant>` ⇒ main loop sets `ControlFlow::WaitUntil(min)` in `AboutToWait`, else `Wait`.
`SessionRecovery { rid, last_ok, last_err, .. }` (frozen here, in `scheduler.rs`, so F1 and F2 can both build against it without waiting on each other's field additions).
`IoWorker::spawn(wake: Box<dyn Fn() + Send>)`; `submit(key, job: Box<dyn FnOnce() -> Completion + Send>)` — a generic job runner, not a typed `Job::{Snapshot, Retire}` holding a `RecoveryStore`: F1 builds its recovery closures over `RecoveryStore::{write_generation, retire}`, and S6 reuses the same worker for its Export job instead of standing up a second thread and a second writer; `try_completions() -> Vec<Completion>`; `shutdown(self)` drains the queue then joins (quit path: all retires finish before exit). FIFO on one thread = writes serialized per destination. `wake` is an `EventLoopProxy<()>::send_event(())` closure in `main.rs`, a counter in tests. The worker never touches an `Editor`.

### 3.8 Recovery UX + real-file save integration (wave 2)
- Launch: `RecoveryStore::open` + `cleanup_completed` + `scan`. Orphans ⇒ Start's Recovery section (the one home) and, when a file intent skipped Start, a one-line SEAM strip below the app bar: **Varos closed unexpectedly. Recovery copies are available.** / "Review copies from your last session before continuing." / **Review Recovery · Later** (Review = show Start). Store failure ⇒ status "Recovery unavailable" (no fallback directory).
- Recover: `scan`'s lock on the entry (the claim) → `load_best` → `doc_from_blob` (+ size cap) → new session, dirty, pathless, named `<name> (Recovered)`, keeping the same `rid` and its lock (the session keeps writing into it; generation N-1 still holds the source until superseded) → strip **Recovered “{name}” from {time}.** / "Save this copy to keep it. Your original file has not been changed." / **Save As…**; `fell_back` adds "The newest copy was damaged; the previous copy was used." Save As default `<name>-recovered.vrs` in the original folder. Failure stays in the list with its reason.
- Discard: **Discard recovery copy of “{name}”?** / "Unsaved changes in this copy will be lost." / **Discard · Cancel** (Cancel default) → `retire`. Later: hide the strip for this run; next launch offers again.
- Retirement: clean after explicit Save/undo-to-saved ⇒ `Retire`; newer edits keep protecting. Don't Save ⇒ retire after the close commits. Successful Save As of a recovered session ⇒ clean ⇒ retire. Normal quit ⇒ every session retired, `IoWorker::shutdown` drains.
- Status (mirror in the status bar; home = Document section from S1): "Saving recovery copy…", "Recovery copy saved at 14:32", "Recovery waiting for edit to finish", failure **Recovery copy couldn't be saved. Save your document now.** **Retry · Save…**; off: **Recovery is off. Save regularly to keep your work.** Document home gets the Recovery on/off switch (app-wide setting, persisted in `settings.json`) and "Last recovery copy: 14:32 · <folder>".

## 6. Risks / open questions (each with a default so execution never blocks)
1. **S1 API drift** (empty workspace, outcome hooks, checkpoint, recovered-session constructor). §3.9 has already been corrected against S1's merged worktree (never-empty `Workspace`, `editor.rev`/`transaction_open`, no `content_checkpoint`); it is the checklist the moderator ticks before starting E2/F1/F2, not a placeholder left to "adapt" on the day.
2. **Durability is platform-specific and Linux CI cannot prove it.** `F_FULLFSYNC`, directory sync on APFS, Windows sharing violations are verified by reading std source + Mac hand test (§1 step 4/6), not by CI. Default: honest `WriteOutcome` + Mac-only hand evidence; Windows stays compile-only (STATUS).
3. **UI-thread clone cost / event-loop pauses.** A `Document` clone per snapshot on huge files, and macOS modal dialogs or live resize pausing `AboutToWait`. Default: measure clone time on perf-harness scene B at 10× and log it in GATE_LOG; a paused loop only delays the next snapshot (no data race — the worker keeps finishing jobs).
4. **Start needs an editor-free UI path** in a 6 000-line editor-bound `ui.rs`. Default: `Ui::run_home` (S1-9) instead of threading `Option<&mut Editor>` through every panel.
5. **Q1 Local clock text** needs a time-zone source. Default: direct `chrono` (clock) dep, zero new crates in the lock. Fallback if rejected: relative text ("saved 2 min ago") from `time_text::relative`.
6. **Q2 Async real Save** (spec §3 "Save I/O off the UI thread"). **Decided (recorded known deviation from the accepted spec):** S3 keeps Save synchronous through the durable writer, accepted because the Save dialogs already block; move it onto the I/O worker in S6 if a 10 MB save measures >100 ms on the Mac.
7. **Q3 Recovered-session identity:** adopting the orphan's directory (not copying it). Default: adopt — the source stays as generation N-1 until two newer copies exist, and a second crash still leaves the newest content recoverable.
8. **Q4 Mac window memory** now possible through the resolver. Default: A keeps it off. QUICK_WINS QW2 is dropped as a separate quick win; turning it on (together with the on-screen clamp) is a small follow-up after A merges. Crash log is enabled from A.
9. **Q5 Settings location of the Recovery switch:** spec puts it in the Document home though it is app-wide. The Document home already exists (`ui.rs:4794 document_section`, in the Properties dock when nothing is selected) — S1 builds none. Working assumption (see Needs Ahmed): F1 adds the Recovery rows there, labelled "Recovery (all documents)".
10. **Q6 Stale hidden temp files** in user folders after a crash mid-save. Default: remove exact-pattern siblings after the next successful save of that file; never scan other folders.
11. Autosave is not the real file: a crash can lose edits made after the last completed snapshot (≤ ~30 s + write time). All copy says "recovery copy", never "saved"; the dirty dot never clears from a snapshot.
