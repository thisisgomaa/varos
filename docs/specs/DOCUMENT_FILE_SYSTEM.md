### Lifecycle, identity and tabs

- Launch without file/recovery intent shows Start. New creates a clean, boardless `Untitled-N`; numbering increases for the process lifetime and is not reused on tab close. A pristine empty document closes without prompting. New never clears an existing session.
- Open, Open Recent, command-line paths and OS open requests use one pipeline. Read into a candidate, validate/migrate, then add a tab. Reuse only a pristine empty tab; never replace edited work. Invalid input leaves all sessions, paths, selection and history untouched.
- One document per tab: stable session ID, title, source path, dirty marker, independent Editor/history, selection, active artboard and viewport. Tab index is ordering, never identity. Switching and reordering preserve all state and do not dirty anything. Finish a valid active gesture, or cancel its preview, before switching/closing; no half-gesture snapshot.
- Resolve file identity using normalized absolute path plus filesystem identity when available. Reopening an already-open file focuses its tab without reloading, including a dirty tab; aliases must not create competing writers. Equal basenames show parent-folder disambiguation and a full-path tooltip.
- Save writes native `.vrs`; first Save invokes Save As. Save As changes the session's path/name only after success, leaving the old file intact. Cancel/failure changes neither path nor saved content checkpoint. Block Save As onto another open session's path and focus/explain that conflict.
- Close Tab handles just that session. Close Window handles its documents. Quit handles every workspace. Dirty documents receive Save / Don't Save / Cancel. A pending quit collects decisions in tab order; it does not destroy any session until all prompts/saves succeed. Cancel aborts the remaining quit; earlier successful saves remain saved, and deferred discard choices are forgotten.
- A clean last tab closes to Start. On macOS window close leaves the app available for reopen; Quit exits. On Windows closing the last window exits after guards. Reordering ships; dragging tabs between windows and creating extra document windows are later, with session IDs designed to survive the move.
- Dirty means a change to authored content or document output settings: paths, nodes, artwork visibility/locks, names, artboard geometry/background/clip, guide geometry and PPI that changes physical output. No-op edits and canceled gestures are clean. Selection, active layer/artboard, tool choice, pan/zoom/fit, display units, ruler origin, rulers/guides visibility, guide locking, snapping preferences and “Move artwork” mode never dirty the file.
- Keep UI preferences in session/app state. S1 may retain legacy serialized preference fields for compatibility but excludes them from the content comparison; undo must preserve current navigation/preferences. S5 formalizes their compatibility mapping. Never ignore authored artwork changes merely because they share a command with a preference.

### Start, recent files and recovery

- Recent list: last 20 successful native opens/saves, newest first, deduplicated by identity; failed operations, exports and recovery snapshots never add entries. Store name/path/last-opened time locally. Remove from Recent and Clear Recent affect only the list. Missing entries offer Locate… / Remove / Cancel; Locate validates before updating the record.
- Start owns New, Open and Recent; templates/presets are later, with no enabled empty Templates route. With documents open, Home returns to Start without closing tabs; selecting a tab returns to its canvas. Explicit OS open intent takes priority over Start.
- Autosave means **separate local recovery snapshots**, never silently writing the real file and never clearing the dirty dot. Default on; after changed content, snapshot every 30 seconds at the next settled transaction boundary, without resetting the deadline on every edit. Long in-progress gestures defer with visible “Recovery waiting for edit to finish”.
- Snapshot immutable content plus session UUID, original path, display name, source fingerprint, content checkpoint, format version, timestamp and checksum. App-owned manifest + versioned model blob; no PDF projection needed. Keep the last two complete generations per session, atomically publish manifest last. Never overwrite the last good generation on failure.
- On next launch scan orphaned sessions, not just a panic flag (force quit/power failure may bypass hooks). Validate snapshots with the same model limits as Open. Offer name, original location and snapshot time with Recover / Discard / Later. Later retains the offer; Discard requires confirmation. A corrupt newest snapshot falls back visibly to the previous valid generation.
- Recover opens a separate dirty, pathless session named `<name> (Recovered)`; original path is informational. Save invokes Save As, defaulting to `<name>-recovered.vrs`. Never overwrite or auto-merge the original; if both are open they remain distinct. A damaged/unsupported snapshot is retained with a readable explanation, not silently deleted.
- Successful explicit save retires snapshots only through the saved checkpoint; newer edits remain protected. Explicit Don't Save discards that session's recovery after the close transaction commits. Successful recovery Save retires its source snapshot. Unresolved recovery is never age-deleted; completed-session leftovers are removed on next startup.
- Visible status: “Recovery copy saved at 14:32” / “Saving recovery copy…” / persistent failure with Retry. Document home contains Recovery on/off and last success/location. Turning it off explains that existing copies remain. Local only, no uploads; no content in crash logs. ADR-0007's visibility principle is borrowed, not misrepresented as an autosave ADR.

### Association and export boundary

- macOS: handle Finder/Launch Services **open-document events**, including events arriving before workspace initialization and multiple files, through queued OpenPaths; registering `.vrs` alone is insufficient. Normal Finder/Dock launch reuses the running app; do not invent a Windows mutex mechanism for macOS. Protect duplicate-process writes even when launched unusually from a terminal.
- Windows: preserve the existing mutex + WM_COPYDATA handoff and route received files into independent tabs. Validate handoff payload length/encoding; queue until ready; duplicate events focus the same tab. P5 is only closed after cold/warm double-click tests, not a compile check (`varos/crates/varos-app/src/single_instance.rs:41–73`, `:252–285`; `varos/crates/varos-app/src/main.rs:866–875`).
- Export belongs to this system as a reachable home, format choice, scope, destination, progress/cancel/result flow. PDF ships now using the existing vector backend; PNG/SVG appear disabled with “Not available yet”, and their engines/settings/batch variants are later systems. No enabled dead button, no screenshot-of-canvas export.
- Default PDF deliverable contains rendered pages **without the private editable model**, so hidden/off-page working content is not leaked through an attachment. Native `.vrs` remains fully editable. Existing `write_pdf` embeds the model unconditionally (`varos/crates/varos-pdf/src/lib.rs:72–78`, `:251–266`); S6 must separate these output modes, not rename `.vrs` bytes to `.pdf`.
- Export scope: All visible artboards (default), Active artboard, or Artwork bounds for boardless content. Hidden boards are excluded; all-hidden or empty scope disables Export with a reason. Clip each page to its chosen bounds, include intersecting visible artwork, preserve opacity/transforms; PDF has one page per chosen board in document order. No forced dummy board for deliverables.
- The native container may retain its compatibility fallback page for empty/all-hidden documents; current fallback is at `varos/crates/varos-pdf/src/lib.rs:80–93`. Export never changes the document path, content, history, dirty checkpoint or native recents. Destination defaults to `<document-name>.pdf`; existing destination requires overwrite confirmation.
- Foreign PDF/AI/SVG import is out of scope: [SAVE_EXPORT_PLAN §3 firewall](../reference/SAVE_EXPORT_PLAN.md). A PDF with a valid embedded Varos model is a native compatibility input even when named `.pdf`; its next Save offers `.vrs`. An ordinary PDF is refused with an explanation, never treated as an empty editable document. External PDF tools may strip the model; Varos cannot promise editability after their re-save.

### Format versions, migration and validation

The editable JSON is the source of truth; `.vrs` remains a PDF container under ADR-0003. Container generation and model schema number are distinct: advancing `VRS_VERSION` does not mean abandoning the V1 container decision.

**The hole:** `VRS_VERSION = 1` and its comment says only wrapper changes require a bump (`varos/crates/varos-core/src/file.rs:11–12`). Newer-number rejection already precedes typed Document decoding (`:27–38`). But `role`/`mask_child` were added with defaults and a no-bump comment (`varos/crates/varos-core/src/model.rs:267–270`, `:319–329`). Defaults protect *new readers of old files*, not old readers of new files. An older same-number Serde reader can discard unknown mask semantics and re-save data loss. This is a compatibility consequence of the schema/loader, not a reproduced old-binary test in this docs session.

- S5 writes **version 2 for every new save**, in both JSON wrapper and PDF catalog; preserves known mask/transform fields from existing v1 files. The new writer must never label richer semantics as v1. Already distributed binaries cannot be repaired retroactively; v1 files already damaged by re-save cannot be reconstructed.
- Bump on **every non-additive-safe change**, including optional/defaulted fields whose omission changes artwork, structure, editability or meaning; removing/renaming fields, changed units/defaults and new enum variants qualify. “Additive-safe” requires proof that older read→save preserves authored meaning and all required data. With unknown-field dropping, new authored metadata normally requires a bump; optionality alone is not proof.
- Refuse `file_version > supported_version` before typed model decoding, without view-only editable fallback or resave. Reject missing/zero/unknown versions rather than guess. Cross-check PDF catalog version with embedded wrapper when both exist; reject disagreement. No downgrade-save mode in this system.
- Migration is explicit, deterministic, sequential and pure; retain the original bytes until user Save. Migration success opens clean with “Opened an older file. Saving will update its format.” Migration failure never installs a partial document or modifies disk. Unknown authored fields/enums fail closed unless the reviewed schema explicitly preserves them losslessly.

| Input | Proposed v2 reader behavior / fixture requirement |
|---|---|
| Legacy raw JSON, wrapper v1 | Bounded decode → explicit v1→v2 migration; tree-less groups converted with preserved order; missing artboards get legacy default, explicit `[]` stays boardless. |
| PDF + v1 JSON (including files containing role/mask_child/xform) | Extract bounded payload → same migration; absent role/mask defaults Normal/None; present values preserved, never flattened away. |
| PDF/raw JSON + v2 | Validate current schema; no migration. New saves always emit PDF + v2 JSON. |
| Versions above 2, invalid version, malformed/ambiguous container | Refuse with a readable reason; preserve current workspace and source bytes. |
| Future vN→vN+1 | Add named transform, defaults/semantic rationale, old/new fixtures and rejection fixture before shipping writer. Never reinterpret v1 to hide another schema change. |

Compositor lesson: document the project format, enumerate version transitions, and reject invalid input **before replacing the live document**. The [study](../studies/2026-09-23-COMPOSITOR_UI_STUDY.md) lists its format source; inspected upstream snapshot `c802b199` documents this at [docs/project-format.md:5–23](https://github.com/robbietilton/Compositor/blob/c802b199b018228be27a031f955ca5e03b184e7c/docs/project-format.md#L5). Borrow the discipline, not its raster-specific limits or package format.

Proposed initial limits, deliberately explicit and subject to S5 corpus measurements: 256 MiB input file, 32 MiB decoded JSON/model, 100,000 PDF objects and model nodes each, 1,000,000 total anchors, 1,000 artboards, 64 scene-tree levels, 64 PDF reference/name-tree levels and 128 JSON nesting levels. Cumulative decoded PDF streams are capped at 64 MiB; a compression-ratio check alone is insufficient. Over-limit input fails with the relevant number, never truncates artwork. Apply matching validation before Save so this build cannot write a document it will refuse to reopen; a refused save leaves the session dirty and recoverable in memory, with an explicit recovery-size warning if snapshots also exceed their limit.

- Order: bounded file read → bounded PDF parse/traversal/decompression → version gate → bounded schema decode → legacy structural precheck → migration → full semantic validation → candidate Editor creation → atomic workspace installation. No recursive `sync_tree` on unvalidated input.
- Reject cycles, repeated ownership, dangling IDs, duplicate IDs, invalid node kinds/references, invalid mask-child parentage, non-finite coordinates/transforms, negative sizes/strokes, invalid opacity/colors and invalid units/PPI. Re-derive next ID using checked max+1; reject exhaustion. Empty artboards are legal; sanitize only transient selection/active indices, never repair away authored mask semantics.
- A parser that allocates unbounded decompressed streams before returning cannot satisfy these caps; enforce limits inside its reader/decompressor or change the adapter before claiming S5 passes. Current load reads the full file, decompression has no cap here, and name-tree traversal recurses (`varos/crates/varos-pdf/src/lib.rs:36–43`, `:343–379`); `doc_from_blob` calls `sync_tree` immediately (`varos/crates/varos-core/src/file.rs:36–38`).
- S5 produces the public `docs/reference/VRS_FORMAT.md` in its future implementation order: exact JSON envelope, PDF keys, migrations/defaults, limits, failure policy, examples and golden fixtures. This docs-only task creates **only this spec**, not that second file. Preserve charter round-trip law: load → save A → reload equal Document → save B with A == B.

## 3. Architecture

**Flow:** native menu / in-app menu / shortcut / Start / tab / OS event → `AppCommand` → app coordinator → core Editor/EditCommand + pure format transforms → app effect runner → result addressed to the initiating session.

App owns conceptual `Workspace { documents: Vec<DocumentSession>, active: Option<SessionId> }`. Each `DocumentSession` owns `{ id, editor, view, path, file_identity, untitled_number, saved_content_checkpoint, recovery_state, pending_job }`. Only its Editor owns its Document and history; no second mutable document copy in UI. Renderer/UI bind to the active session; jobs carry stable session ID + content checkpoint so switching/reordering cannot save another tab.

| Owner | Responsibility |
|---|---|
| `varos-core` | Document, Editor/history, EditCommand, content-equivalence/checkpoints, versioned JSON encode/decode, pure migrations and validation. No UI/window/GPU, dialogs, timers, platform locations or new app-effect dependencies. |
| `varos-pdf` | PDF bytes ↔ embedded model bytes; bounded container parsing, PDF page generation and native-versus-deliverable mode. No window, recents or recovery policy. |
| `varos-app` | AppCommand/workspace/session lifecycle; rfd dialogs; paths, native events, clock/timers, file I/O/atomic replacement, locks, jobs, recovery/recents/settings and visible feedback. |
| `varos-render-wgpu` | Active document presentation using existing core data; no persistence policy or document ownership. |

Current core contains path I/O helpers and PDF calls `write_atomic` (`varos/crates/varos-core/src/file.rs:44–61`; `varos/crates/varos-pdf/src/lib.rs:22–42`). Proposed implementation moves effectful writing/reading orchestration into app while leaving byte/blob functions pure; update callers/tests without changing crate dependency directions. Do not pretend this separation already exists.

AppCommand vocabulary (internal enums, not a plugin API):
- Lifecycle: `NewDocument`, `OpenDialog`, `OpenPaths(paths, origin)`, `OpenRecent(id)`, `Save(session)`, `SaveAs(session)`, `CloseDocument(session)`, `CloseWindow`, `Quit`.
- Navigation/settings: `ActivateDocument(id)`, `ReorderDocument(id, position)`, `ShowStart`, `RemoveRecent(id)`, `ClearRecent`, `LocateRecent(id)`, `SetRecoveryEnabled(bool)`.
- Recovery/export: `RequestSnapshot(id)`, `ReviewRecovery`, `Recover(id)`, `DiscardRecovery(id)`, `DeferRecovery`, `ShowExport(id)`, `ExportPdf(id, options)`, `CancelJob(job)`.
- Continuations: `DialogResolved(request, choice)`, `OpenCompleted(request, result)`, `WriteCompleted(job, checkpoint, result)`; duplicate events cannot apply twice. Existing panel/window effects also enter `AppCommand` to fulfill F4.2; document edits still delegate to EditCommand, transient input to declared Editor interfaces as in F4_DESIGN.

### State machine and storage safety

| Event | Content state / operation outcome |
|---|---|
| New / validated Open | CleanUntitled / CleanSaved; no unsaved marker. |
| Content differs from saved checkpoint | Dirty, including while a changed gesture awaits commit; Save/Close first resolves that transaction. View-only changes leave state alone. |
| Undo/redo returns to saved authored content | Clean again. Use pure content comparison/checkpoint equivalence; `rev` remains a change signal, not proof of dirtiness. |
| Save starts at checkpoint C | Saving(C) overlays current content state. Snapshot immutable bytes; keep existing file/path until successful replacement. |
| Save success / cancel or error | Saved checkpoint becomes C, but newer edits remain Dirty / retain prior checkpoint and path. Pending close waits for success and rechecks dirtiness. |
| Snapshot success | RecoveryAvailable(C); document stays Dirty. Snapshot error is visible; previous generation remains. |
| Startup orphan → Recover | Recovering while validating → RecoveredDirty in a new session; failure stays in recovery list. |
| Close/quit request | AwaitDecision → Saving or DeferredDiscard → Close only when transaction completes; Cancel/failure returns to open state. |

Use a single in-flight write per session and serialize writes per destination identity. Save/Export I/O runs off the UI thread from immutable snapshots; no background worker mutates Editor. Cancel is honored before atomic replacement; after replacement report success, not a false cancellation. Shutdown drains/cancels jobs before discarding sessions. No success message before durable completion.

Atomic replacement is not the same as power-loss durability: current helper writes a fixed sibling `.vrs.tmp` and renames, without sync (`varos/crates/varos-core/src/file.rs:49–54`). Proposed real-file and snapshot writes use unique sibling temporary files, full write + flush/sync, platform atomic replace (Windows replacement semantics included), then directory durability where supported. Keep old file intact on pre-replace error; if post-replace durability is uncertain, retain dirty/recovery and say so. Never delete destination first. Detect another process's changed/deleted source via fingerprint before overwriting; offer Save As… / Replace Anyway… / Cancel, with explicit confirmation for replacement.

Platform data root: macOS `~/Library/Application Support/Varos/`; Windows `%APPDATA%\Varos\`, resolved by platform APIs, never current working directory. Under it: `Recovery/<session-uuid>/` generations + manifests, `recent.json`, `settings.json`, `Logs/crash.txt`. Share one app-path resolver with window settings/crash reporting; current paths only consult APPDATA (`varos/crates/varos-app/src/main.rs:431–438`). Failure to create storage leaves editing available but displays “Recovery unavailable”; never silently fall back to an unknown directory. Use per-process/session ownership locks to avoid treating live sessions as crash recovery.

### ONE-HOME and hard laws

| Action family | Single home; all other routes are mirrors |
|---|---|
| New / Open / Recent / future Templates | Start section in the central workspace; native File and hamburger dispatch its commands. |
| Title/path / Save / Save As / Close / recovery status | Document section, reachable from the active tab's document-details control; dirty prompt is this same lifecycle decision flow. |
| Activate / close / reorder tabs | Document tab strip; Window menu and shortcuts dispatch the same commands. |
| Recovery choices | Recovery section on Start; banner and Document status jump to it, not a second recovery dialog implementation. |
| Export / destination / format options | Export section in one docked workspace box; top Export and File → Export… reveal the same instance. |
| Quit / Close Window | Workspace lifecycle coordinator, reached through app/window controls; per-document decisions use Document home. |

Remain native Winit + Egui on WGPU, never eframe/web UI; core stays GPU/window/UI-free. Tests never construct Renderer/EventLoop. No new crates or dependency-edge changes are required by this design. ADR-0001/0002/0003/0005/0006 stay intact; AppCommand already has ADR-0002 authority, so **no new ADR for F4.2**. ADR-0007 is unchanged (recovery visibility is an analogous product policy). ## 4. UX spec (Illustrator + Figma conventions, our visual law)

Use familiar local-document conventions—independent tabs, native file pickers, Save As and dirty decisions—with Figma-like direct tab navigation. These are design choices, not a claim of feature parity or cloud autosave. Our [visual law](../UI_DIRECTION.md) wins: warm `#141313`, azure `#0c8ce9` only for active/selection/focus, typography-only hierarchy, no shadows or animation, 3px controls/8px boxes. Reuse `shell/tokens.rs`, whose actual values are at `varos/crates/varos-app/src/shell/tokens.rs:25–59`; never introduce a second token palette. Native OS dialogs keep native styling.

Naming: tab `Untitled-1`, native window `Untitled-1 — Varos`; saved tab `Logo.vrs`, window `Logo.vrs — Varos`. A small neutral dirty dot precedes the name; accessible label “Logo.vrs, unsaved changes”. Full path is visible in Document home and tab tooltip, not permanently crammed into the title. Active document name always matches canvas/layers. Dot remains visible when hover reveals ×, with separate close hit target and accessible “Close Logo.vrs”.

| Situation | Exact copy and actions |
|---|---|
| Close dirty document | **Save changes to “{name}”?** / “Your changes will be lost if you don't save them.” / **Save · Don't Save · Cancel**. Save is default; Escape/closing the prompt means Cancel. Never default to discard. |
| Quit with several dirty tabs | Same prompt per document, plus “Document {i} of {n}”. No ambiguous “Discard all”. Activate the relevant tab behind the prompt. |
| Save As | Native title **Save Varos Document**; filename `Untitled-1.vrs` or current basename; type **Varos document (.vrs)**; **Save · Cancel**. Existing file: native **Replace · Cancel** confirmation. |
| Open | Native title **Open Varos Document**; types **Varos documents (.vrs)** and **Varos PDF documents (.pdf)**; multi-select; **Open · Cancel**. PDF filter does not promise foreign import. |
| Save failed | **Couldn't save “{name}”.** / “Your changes are still open. {reason}” / **Try Again · Save As… · Cancel**. Cancel returns to the document and aborts pending close. |
| Open failed / limits | **Couldn't open “{name}”.** / “{reason}. Your open documents have not changed.” / **OK**. Example reason: “The editable model exceeds the 32 MiB limit”. |
| Newer file | **This file needs a newer Varos.** / “It uses file format {n}; this build supports up to {m}. Update Varos to open it. The file has not been changed.” / **OK**. No silent update or invented updater button. |
| Missing native model | **This PDF has no editable Varos document.** / “Open the original .vrs file. Importing other PDFs is not available yet.” / **OK**. |
| Recovery on launch | Banner **Varos closed unexpectedly. Recovery copies are available.** / “Review copies from your last session before continuing.” / **Review Recovery · Later**. |
| Recovered document | **Recovered “{name}” from {time}.** / “Save this copy to keep it. Your original file has not been changed.” / **Save As…**. |
| Discard recovery | **Discard recovery copy of “{name}”?** / “Unsaved changes in this copy will be lost.” / **Discard · Cancel**, Cancel default. |
| Recovery failure / off | **Recovery copy couldn't be saved. Save your document now.** / **Retry · Save…**; when disabled: **Recovery is off. Save regularly to keep your work.** |
| PDF export | **Export** home; **Format: PDF**, **Pages: All visible artboards**, page count + destination; “For sharing. Editable Varos data is not included.” / **Export… · Cancel**. Native destination title **Export PDF**. |
| Export status | “Exporting PDF…” + **Cancel**; success “Exported {filename}.” + **Show in Finder** / **Show in Explorer**; failure “Couldn't export PDF. {reason}. Your document has not changed.” + **Try Again · Cancel**. |

Close-tab flow: ×/middle-click/⌘W resolve the target session → if dirty prompt above → Save may open Save As → cancel/error retains tab and focus → success or Don't Save removes tab → choose right neighbor, otherwise left → empty workspace shows Start. Closing an inactive dirty tab must identify that tab, never save the active one. Keep keyboard focus within prompts and restore it to the initiating surface afterward; document commands never fire through a modal.

Keyboard: **⌘N New; ⌘O Open; ⌘S Save; ⇧⌘S Save As; ⌘W Close tab; ⌘Q Quit**. Windows equivalents use Ctrl for N/O/S/Shift+S/W and Alt+F4 for window close; File → Exit calls Quit. Menus and physical keys dispatch once through command IDs, not synthetic key events. Provide tab traversal (Ctrl+Tab / Ctrl+Shift+Tab) and keyboard reorder in the tab context menu; modal text inputs keep normal editing keys. Native menu enabled state mirrors command availability, including no-document and in-flight-job states.

Start page layout: inside the existing central workspace box, a restrained “Varos” title followed by a single New document / Open… action row with shortcut hints, then a RECENT heading and a dense text list of filename, muted parent location and last-opened time; recovery rows sit above Recent only when needed. Empty copy is “No recent documents. Create a document or open a .vrs file.” At narrow widths, stack location below name and keep actions reachable; long paths elide in the middle with full tooltip. No hero illustration, gradient, thumbnails, cards, tips carousel or decorative icons; templates get a section only when implemented. New immediately opens the boardless canvas, preserving A8a.

## 6. Risks & open questions

- **D1 — Scope/priority/platform decision:** adopt this as the first complete system, absorb F4.2 and charter parked trust work, replace fake tabs with real sessions, and authorize S4's Windows exception + test access. Recommended yes; STATUS:29 otherwise forbids Windows-specific work/hand-testing. Record the dated decision/flag changes in the future work order; do not imply all Windows product work resumes.
- **D2 — Workflow/recovery decision:** approve Start by default, boardless New, recovery on at 30 seconds with two generations, recover-as-copy and explicit discard. Recommended yes. Interval/retention are starting policy, not benchmarked performance; status must disclose overdue/failed recovery. No forced session restoration of clean tabs in this release.
- **D3 — Compatibility/delivery decision:** approve v2 for all new saves, conservative version bumps/refusals, bounded migrations and pure-PDF export. Recommended yes; accept that old Varos refuses new files and `.pdf` Save becomes native-open compatibility + Export. Approve the narrow companion ADR required by ADR-0004 before S5; no container replacement or public plugin contract.
- **Autosave versus real-file atomicity:** they are separate transactions and locations. A crash can lose edits after the last completed snapshot; do not promise zero loss or trust a successful rename as power-loss proof. Network/removable-volume failures need honest errors and conflict checks.
- **Size/latency:** `.vrs` stores rendered PDF plus model, and history already holds up to 200 Document copies (`varos/crates/varos-core/src/editor.rs:2874–2884`). Recovery stores model only; serialize only when content changed, one job per document. Measure large-file memory/time and UI responsiveness before ratifying caps; no speculative undo rewrite in this system.
- **macOS process/events:** verify the chosen winit/AppKit open-event bridge on the bundled app without stealing native menu delegation; normal Finder reuse does not prove arbitrary CLI launches are single-instance. Cross-process fingerprint/ownership protection is still needed. Exact adapter is an S4 engineering spike within its day cap.
- **Validation effort:** PDF parser allocation limits may exceed S5's day cap; reveal that at entry, reuse F7 hardening work, and keep the release gate closed until bounded parsing is real. Never move a check after live replacement to meet a deadline.
- **Privacy and fidelity:** pure PDF must omit all embedded editable data, including hidden objects; check emitted streams, not just visual pages. Existing renderer/export feature mismatches (including masks) must be exposed by fixture comparison; fail/disable unsupported export with a reason instead of silently misrendering. New rendering feature systems are not smuggled into this plan.
- **Unanswered engineering checks, not extra owner decisions:** exact platform durable-replace primitive, macOS event adapter and measured input budgets are implementation-review questions. No installer/signing/cloud/template/import system is assumed complete when these six gates close.
